question across the project pool"*. The incident is loderite `id:ed3a`, which carried the

lint: **exit 0, zero findings**. Rule 3(h) validates the marker's grammar and never reads the

**That work LANDED tonight** (`e43a2f46`, `82cf83ce`, `9440c3bb`, id `6621`). The honest
result: **all three re-asks now have a mechanism and NONE is airtight.**

- **(1) a later author edits the marked line.** Caught at relay review only, by `review.md`
  §2b.10's grep over the reviewed diff, and only if a reviewer actually runs. A `/meeting`
  write-back or a hand edit on `main` never passes through `review.md`, so it escapes.
- **(2) a meeting agenda re-opens it.** Caught only if the agenda is built from
  `gather-human-backlog.sh`, which now emits an additive `answered_question` row FIRST per
  repo naming the citation. An agenda that reads `ROADMAP.md` directly escapes.
- **(3) an apex session asks again.** Same collector path, same escape hatch.

The common escape is **any reader that bypasses the collector**. Closing that is the next
design question and it is UNOWNED.

What IS fixed unambiguously: the marker is no longer forgeable. `executor-contract.md` rule 8
(contract **v16 -> v17**) forbids an executor writing either the marker or its citation, and
`review.md` §2b.9 has the reviewer grep executor-attributed commits for it, mirroring
`@owner-accepted` (id:8089). Before this, "owner-only" was prose nothing enforced.

Rule 3(h) was hardened in `e43a2f46`: fenced code blocks no longer wrong-fire, the backtick
mask handles multi-backtick runs, a citation must resolve to a regular FILE not just any
path, `#anchor` is verified against real headings, and matching is case-insensitive.
**Documented rather than silently kept:** 3(h) scans column-0 checkbox lines only, so a
