1. `2d17` -- `shape-prose` saturated at ~114 findings, so it could not surface #115.
2. `roadmap-lint`'s SCOPE-TABLE-DRIFT -- `[[ -n "$reqs" ]] || return 0`: no message, exit 0.
   Relocating one item's body would have silently deleted the check.
3. `9ce0` -- I removed the mechanism and left the indicator reporting success. Mine.
4. The staleness detector's printed remedy was **destructive** -- a single-ledger regen would
   have truncated the shared baseline and turned 87 warnings into errors.
5. `_SEP_RE` ASCII-only -- refused the exact population it existed for, reporting "under 25
   chars would move": true and completely misleading.
6. `MIN_MOVED_CHARS` measured what LEAVES, never what the split COSTS. `id:625a` GREW
   349 -> 355 and passed every check.

while the code spanned FOUR; BOTH examples in `lib-anchored-id.sh` had rotted, one WITHIN THE
HOUR. Neither could ever turn a test red.

## 6. Traps paid for, so you do not pay them again

- **An aggregate count hides a per-item loss.** The token-carriage check said "zero tokens
  lost" while `[ROUTINE]` went 70 -> 17 -- entirely archived stubs. Only the per-item pass
  (791 surviving items) found the 4 real losses, and all four turned out to be tokens QUOTED
  in prose, not own lanes.
- **TWO of my predicates turned out REPO-SHAPED, not structural. Assume the next one is too.**
  1. "Readers anchor on `^- \[ \]`, so they do not read bodies" is safe HERE (bodies are in
     notes) and VACUOUS in a repo where the body IS the item line. Same regex, opposite
     conclusion.
  2. **The discriminator behind section 6's "4 losses, all quoted, zero own-lane" is
     "own lane is LEADING, quoted tokens are elsewhere" -- and that is a fact about THIS
     repo's grammar, not a general test.** loderite legitimately places `@owner-answered:`,
     `answer-src` and a trailing `@manual` AFTER the title, so position does not separate
     own-carrier from mentioner there at all; the positional table looks beautifully clean
     and is an artifact. They caught it by sampling instead of shipping it (their `id:3c83`
     carries `@manual` for real in a leading position; `id:04eb` carries `DECOMPOSED` as its
     own gate marker AND quotes it in prose on the same line).

  So my four-losses result is a claim about my grammar as much as about the trim. **The real
  discriminator is "is this token the item's OWN marker" -- a GRAMMAR question, not a
  POSITION question -- and the answer differs per repo.** That belongs in `9ce0`.
- **`# roadmap:` and `# fails-against-mutation:` are mutually exclusive** -- see `7c82`.
- **A pin is a property of the CONSUMER'S resolution path**, not the producer's HEAD. "I am at
  sha X" and "the consumer RUNS sha X" are separate claims, and only the consumer can verify
  it. Verified here: `make status` all symlinks, no stale copies.
- **Documenting a marker defect corrupts marker-counting tools.** `TODO.md:679` carries FOUR
  id markers because it is an annotation ABOUT id-misattribution. The residue is the cost of
  the explanation.
