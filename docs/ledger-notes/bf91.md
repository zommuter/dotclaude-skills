### The defect

`classify-repo.sh`'s ledger-note pointer regex matches a note path quoted in PROSE, not only a
genuine `detail:` pointer. `relay/scripts/classify-repo.sh:187`:

```python
LEDGER_NOTE_POINTER_RE = re.compile(r"((?:[A-Za-z0-9_.-]+/)+[0-9a-f]{4}\.md)")
```

There is no `detail:` anchor and no pointer context of any kind -- it is a bare path shape, so
any `<dir>/<4-hex>.md` string anywhere in the scanned text is collected as a pointer at
`:199`. Live case: `RELAY_LOG.md:1189` contains a sentence saying that a particular note does
NOT exist (the path is deliberately spelled split in the inbound report to avoid re-triggering
the bug in the report itself), and the prompt-size gate then charges the fail-safe 32,768 B
for that non-existent file.

### Direction of the error is safe; the class is not

It over-counts only, so the gate goes PESSIMISTIC and refuses more often than it must -- it
never lets an oversized prompt through. That is the safe direction, which is why this is filed
as a defect rather than an incident.

The reason it still matters: this is the `id:fff8` MEASUREMENT-ARTEFACT class occurring
**inside the measuring tool**. A gate whose own input is inflated by prose cannot be trusted
to report how close a repo is to the limit, and a pessimistic gate that fires for phantom
reasons is how a real budget signal gets ignored.

- **Acceptance**: a note path appearing in prose (no `detail:`/`answer-src:` pointer context)
  is NOT collected as a ledger-note pointer, and the prompt-size gate stops charging the
  fail-safe size for it; genuine `detail:` pointers are still collected unchanged.

- **Done-check**: a fixture whose `RELAY_LOG.md` names a note path in a prose sentence asserts
  the gate's byte total excludes it, and is RED against the current bare-path regex.
