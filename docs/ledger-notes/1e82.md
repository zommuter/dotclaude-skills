## Two distinct halves, and the second is the one a192's line recorded

1. **No caller at all.** Report-only tooling with no invocation is the
   [[relay-builtgreen-but-unreferenced]] class (`id:5367`/`id:2062`): built, tested, green,
   referenced zero times. The banked rule is to run `grep -c <script> relay-loop.js` before
   treating a script as available. Nobody ran it here because the test was green.
2. **No caller passes `EXPIRES_ON_EXTRA_PATHS`.** Even once a caller exists, the env var is
   opt-in and empty by default (`expires-on-scan.sh:87`), scanning only inside the repo. The
   clause that motivated `a192` lives in `~/.claude/CLAUDE.md`, OUTSIDE any repo, so it is
   unreachable by the hermetic test AND by a default scan. This is the half `a192`'s closed
   ROADMAP line already names as residue.

## Why the test could not have caught either

`tests/test_expires_on_edge_guard_a192.sh` pins the scanner's BEHAVIOUR, including cases (f) and
(f2) which prove the default adds no out-of-repo path and that `EXPIRES_ON_EXTRA_PATHS` opts one
in. Both are correct and both pass. A hermetic test cannot observe whether anything in the fleet
calls the script -- that is precisely the observability boundary, not a defect in the test.

## What "done" looks like

A decision on WHERE the scan runs, then the wiring:

* a `make` target for a human-run report (cheapest, matches `control-board.sh`), and/or
* a relay-loop hop, and/or
* a `/relay health` sub-check alongside the other report-only scans.

Whichever is chosen, the call site must pass `EXPIRES_ON_EXTRA_PATHS` with the owner's
`~/.claude/CLAUDE.md` path for half 2 to be discharged, and that path is per-machine, so it
belongs in config, not hardcoded.

## Verification that discriminates

Not "the scan runs green". The check is that an `expires-on:` clause whose owning item has
CLOSED gets REPORTED to a human through a path nobody had to remember to invoke -- and,
separately, that a clause living outside the repo is reachable at all.
