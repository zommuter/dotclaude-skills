## From TODO

**`relay-reconcile.sh --integrate` PUBLISHES to a public remote automatically, which
`id:f66e` forbids.** Observed 2026-09-08 integrating a parked orphan in this repo.

**The evidence.** The integrate recipe's push step is
`git-lock-push.sh --ff-only --all` -- documented that way in `relay/SKILL.md`'s Reconcile
mode, and it does what it says:

```
To https://github.com/zommuter/dotclaude-skills.git
   f6fa91d1..8aecd0f1  main -> main
 * [new tag]           relay-ckpt-20260908-1754 -> relay-ckpt-20260908-1754
privacy-gate: remote 'origin' (fievel:src/dotclaude-skills.git) is a PRIVATE host — skipping leak scan.
```

One operator action (`--integrate <branch>`) pushed to public GitHub with no prompt, no
confirmation, and no mention of publishing in the command's name or its output beyond the
push line itself.

**Why this is a contract violation, not a preference.** `id:f66e` (owner decision
2026-08-22) states publishing to a PUBLIC remote is never automatic. `git-lock-push.sh`'s
own default was narrowed to `origin` ONLY on 2026-08-26 for exactly this reason -- its prior
"push every remote" default is described in `git-diary-workflow/SKILL.md` as "the footgun
this skill's `--remote origin` requirement used to guard against". The reconcile path keeps
that footgun by passing `--all` explicitly, so the 2026-08-26 narrowing does not reach it.

**`integrate.sh` already solved this; reconcile never got the fix.** `id:4d44` gave the pool
integrator per-remote push narrowing via `relay/scripts/lib-private-remote.sh` -- THE single
"is this remote a PRIVATE/LAN host?" predicate -- plus the `ratification_pending` queue, so a
public-remote push is WITHHELD and surfaced for a human to review and push. The reconcile
path calls neither. Two integration paths, one contract, one implementation. This is the
same shape as the bank memory `bump-changelog-reaches-one-of-three-paths`: a rule
implemented on the path its author was looking at.

**Blast radius.** Fourteen of 56 own repos carry a public GitHub remote (re-measured
2026-08-27): `dotclaude-skills`, `zkm`, `toesnail`, `proton-moresync`, and ten zkm plugins.
`relay-reconcile` is a HUMAN-invoked mode, run precisely when someone is disposing of parked
work they have not necessarily read -- an orphan is by definition a `id:f272` "WIP UNVERIFIED
residue" commit. Publishing unreviewed residue is the worst possible default for that verb.

**The privacy gate is not the backstop.** It ran on the public push and logged one hit, but
it is warn-only (`exit 0`, never blocks) and DIFF-scoped, exactly as `id:9bfc` records. It
observed the publish; it could not prevent it. The hit itself was a false positive -- a short
private pattern matching inside an ordinary English word -- which is beside the point.

**Suggested fix.** Route the reconcile push through `lib-private-remote.sh` the way
`integrate.sh` does, so a public remote is withheld and queued via `ratify-queue.sh` rather
than pushed. Do NOT substitute `git-lock-push.sh`'s `is_ssh_url()`: `CLAUDE.md` records that
it is an SSH-AUTH predicate and "fails toward auto-publish", which is the wrong direction
here. A done-check should assert that `--integrate` in a repo with a declared public remote
advances the private remote, leaves the public one unadvanced, and records the withholding.
