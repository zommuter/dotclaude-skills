### The three changes

1. **`id:` becomes POSITIONAL, not a comment.** The item line becomes
   `- [ ] **id:....**`-shaped: the id is a visible token whose POSITION on the line
   identifies it, replacing `<!-- id:XXXX -->` as a trailing anchored comment. Exact syntax
   is the design call, not settled here.
2. **Typed edges stop being comments too** -- `routed:`, `children:`, `children-of:`,
   `gated-on:`, `relates:`, `settles:`, `answer-src:`, `owner-hold:`, `xledger-ok:`,
   `xgate:`, `relay:`, `invocation-flags:`, `claiming:` (the list `LEDGER_EDGE_KINDS` in
   `relay/scripts/todo-conformance.sh` holds; read it there, do not restate it).
3. **Every NON-MEANINGFUL mention must be backtick-escaped or otherwise neutralised.** An
   id quoted as an EXAMPLE is not a reference. Note that such prose "belongs to the
   per-item detail file anyway" (owner) -- so the migration and the `id:0d7c` prose
   relocation pull the same direction.

### Why (3) is not cosmetic -- it is the whole reason the syntax is unsafe today

Measured 2026-09-03:

- **This item's own predecessor is corrupted by it.** `ee62`'s head line carries
  `<!-- id:XXXX -->` and `<!-- routed:XXXX -->` -- *examples from its own prose* -- hoisted
  onto the head line by `ledger-shrink.py`, plus ~300 chars of prose dragged along by an
  unterminated `<!-- xledger-ok:` example. Tracked separately as `id:8372`.
- **30 ledger lines** carry such a placeholder marker (28 `TODO.md`, 2 `ROADMAP.md`).
- Fleet-wide: **58,570 bare `id:XXXX` prose refs, 3,484 ambiguous**; `dotclaude-skills`
  contributes **23,698 (40%)**, of which **`docs/ledger-notes/` is 4,225** -- the trimming's
  own output is now a leading unanchored-reference surface
  (`cartulary/scripts/prose-tail-scan.py`, re-run today).

A marker syntax that a tool cannot distinguish from a quotation of itself is the root defect.
Backtick-escaping is what makes ANY of the three changes mechanically safe to migrate.

### Sequencing

Do NOT run this before `id:03a3`, and do not fold it in. `03a3` migrates 46 repos to the

### Known interactions

  the migration rewrites every marker and would propagate corrupted lines.
- **`id:6059`** -- multi-marker lines are REFUSED. A positional scheme must state what
  happens to a line carrying two owning tokens, or those lines become unwritable in a new way.
- **`id:46f6`/`id:4559`** -- `project_manager/ledger.py:69` reads only the FIRST `gated-on:`
  per line, and `:64-68` strips inline-code spans before finding a gate. So under (3),

  collision must be stated before either lands.
- **`id:1254`** -- the opposite convention: a backticked lane bracket IS the computed lane
  today, because `classify-repo.sh` does not mask backticks. The fleet currently has one
  convention where backticks are transparent and one where they are opaque.
