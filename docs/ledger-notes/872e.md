Idea: record a per-commit signal in git notes so a `git bisect run` wrapper auto-`125`s (skips) commits that can't be meaningfully tested, and so a stale-test/sanity-violated commit is marked. **Crucial nuance the user raised (the design hinge):** bisect runs the CURRENT/uncommitted test (the bug repro) against OLD source — it preserves untracked working-tree files across checkouts and `git bisect run <script>` lives outside the tree — so a "commit X gamed its OWN committed tests" flag is largely ORTHOGONAL to bisectability (bisect may never run X's tests). The signal that genuinely pays off is **runnability**: "this commit doesn't build / the harness can't execute here" → skip. The sanity-violation flag feeds bisect only insofar as a violation made the commit un-testable. **Substrate already exists:** the verify commit-hook writes ephemeral notes on `refs/notes/verify` (`status:pending findings:…`, toesnail id:8757) and `gaming-scan.sh` (id:fa05) is the mechanical sanity detector — a bisect-skip consumer is a natural extension. **Design qs for the meeting:** (a) carrier — extend `refs/notes/verify` with a `runnable:false`/`bisect_skip:true` field vs a dedicated `refs/notes/bisect-skip` ref (a new field bumps the just-FROZEN verify schema `{status,findings}`+`{triaged,processed,verdict,review_me}` — toesnail /relay human 2026-06-16, so it's a deliberate extension not a free add); (b) who writes it (the post-commit HARD tier? gaming-scan? a separate build-probe?) and when a commit is deemed un-runnable; (c) the `git bisect run` wrapper that reads the note and returns 125; (d) notes are local-only + lossy-on-rebase (toesnail D-decisions) — acceptable for a bisect aid, or does it need durability; (e) cross-repo vs per-repo.
