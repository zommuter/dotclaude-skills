## Original title (verbatim, before the `id:64f9` rewrite)

`relay-reconcile.sh` reports FALSE-CLEAN when a run dies without completing the D1 orphan-park rename. It lists only `relay/orphan/*`, but the park (branch rename) is not guaranteed to run on a dying/killed run — so an abandoned worktree left on a plain `relay/<runid>-<verdict>` branch is structurally invisible to the one tool meant to find it. Observed live 2026-07-31 on mathematical-writing: `/relay reconcile .` printed `no parked orphans` while `~/.cache/relay/worktrees/mathematical-writing/relay-20260717-173352-25749-review` (branch `relay/relay-20260717-173352-25749-review` @ f65e67b, 14 days old) sat on disk with two uncommitted files. Found only because a handoff's `git worktree list` happened to show it. Same CLASS as id:4e14 (the false-clean sweep bug) but a different cause: 4e14 was a hand-rolled sweep swallowing errors, this is the canonical tool's SCOPE being narrower than the failure mode. Suggested fix: have reconcile also enumerate `relay/*` branches that have a worktree or no live `claim.sh` holder, and report them as UNPARKED orphan candidates (distinct from parked ones, since disposal differs — an already-merged one is a force-free `git branch -d`).
