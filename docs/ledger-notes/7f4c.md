## The loop: context deaths lock the repo out of dispatch entirely

Every link measured on runs `relay-20260909-143257-21736` and `relay-20260909-185356-12943`,
same repo, same evening.

1. **Deaths park orphans.** Run 1 lost 7 of 10 `execute:dotclaude-skills` children to
   `Prompt is too long` (rule 2c's guard was inert, `id:5295`). Each dead child's worktree was
   commit-and-parked as `relay/orphan/*`, one per item worked: `id:11a4`, `id:799f`,
   `id:aa5e`, `id:b437`.
2. **Parked orphans suppress their items.** `discover-repo.sh` publishes the parked set as
   `unit.suppressed_item_ids` and appends "orphan-parked ... do NOT work id:X" to the reason.
   Run 2's discovery carried, verbatim:

       orphan-parked (id:11a4, id:799f, id:aa5e, id:b437, id:c655)

   Four from run 1's deaths, plus `id:c655`, parked since that morning by an owner-ratified
   `/relay human` disposition (leave-parked as the documented restart point -- a correct call
   whose cost was not visible at the time, and is this item's point).
3. **`id:b09e` SUBTRACTS the suppressed set from the nameable ids.** When the subtraction
   empties the list, `dispatchItemFor(unit)` returns falsy.
4. **An unnamed unit gets no slice.** `ledger-slice.sh` slices BY ID; no id, no
   `slice_path`. Confirmed from the worktree key: `unitKey({..., itemId: dispatchItemFor(unit)})`
   falls back to the literal `repo`, and run 2's execute worktree was
   `relay-20260909-185356-12943-execute-repo-0` -- versus the named `-execute-5295-0` and
   `-execute-aa5e-0` in the same run.
5. **No slice ⇒ the gate sizes the WHOLE ledgers.** `relay-loop.js:3216-3252` has two
   accountings: a sliced unit is charged its slice (~8,857 B average here, ~2.2k tok); an
   unsliced unit is charged `countedLedgersFor` -- which since `id:f3d2` includes every
   pointed-to detail note. Measured: **2,414,015 B ~= 603,503 tok**, reported as ~668,626 tok
   with overhead, against a 100,000 tok Sonnet budget.
6. **Refusal, twice ⇒ `repeatHandbackKind: bug-signal` ⇒ `stopReason: blocked-pending-human`.**
   The repo can no longer dispatch ANY execute unit.

So a context death does not merely lose one unit: it removes a nameable item, and enough
removals un-name the whole verdict, which drops the slice, which switches the gate to an
accounting the repo cannot possibly pass. **The failure is self-amplifying and the repo locks
itself out.** Nothing in the chain is individually wrong -- orphan-suppress is `a4e9-D1`
working as ratified, `b09e`'s subtraction is correct (naming a suppressed item would contradict
the instruction beside it), the slice is right to key on an id, and the gate is right to refuse
an unbounded child. The composition is what fails.

## Why the fail-open does not save it

`id:b09e` documents its no-usable-id path as FAIL-OPEN: the historical plural instruction is
used, "so this can only ever narrow the child's search, never break dispatch." That is true of
`b09e` in isolation and false of the system, because the same condition ALSO removes the
slice, and the prompt-size gate then refuses before any child exists. The fail-open hands the
child a survey instruction it never gets to read.

This is worth stating plainly because the comment is the thing a future reader will trust:
**`b09e`'s "never break dispatch" claim is no longer accurate** once `id:35b7`/`id:e68f`
slicing sits downstream of it.

**Acceptance**: when every actionable id for a unit is suppressed, the pool does NOT emit an
unnamed execute unit that is then refused on whole-ledger size. Pick one and state which:
(a) emit no execute unit at all and surface the repo as orphan-blocked with the reconcile
command -- honest, and it makes the real remedy (`/relay reconcile`) the visible next step;
(b) keep the unit but slice it on the suppressed-but-known items so the gate charges a slice;
(c) name the first suppressed id purely for slicing while keeping the do-NOT-work instruction.
(a) is the conservative default and the one this note recommends; (c) is rejected here as
inviting exactly the imperative conflict `b09e` was written to remove.

**Done-check**: a hermetic test building a unit whose `actionable_routine_ids` are wholly
contained in `suppressed_item_ids`, asserting the chosen behaviour and asserting specifically
that the prompt-size gate is NOT reached with whole-ledger bytes. `make test` green.

**Context**: `relay/scripts/relay-loop.js` (`dispatchItemFor`, `unitKey`/`worktreePathFor:2957`,
the `b09e` subtraction block ~:2960-2975, the gate at :3216-3252),
`relay/scripts/discover-repo.sh` (publishes `suppressed_item_ids`),
`relay/scripts/ledger-slice.sh` (slices by id).
