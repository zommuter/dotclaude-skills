## From TODO

(both halves observed live 2026-08-13). Two distinct defects, one root: consumption is irreversible and unacknowledged. **(A) DURABILITY.** `take` moves each shard to `inject.done/` and emits it; from that moment the unit exists ONLY inside the consuming run's memory. If that run hands back, stops, or drops queued-but-undispatched units (`stopReason: blocked-pending-human` / `user-stop` / quota), the unit vanishes: `peek` is empty, the ledger is unchanged, and NOTHING reports it. OBSERVED: `inj-20260813-193234-4091510-24753` (a `routed:f833` handoff) was consumed by run `relay-20260813-180303-4214`, whose 6 rounds ended `blocked-pending-human`; `routed:f833` was never promoted and the loss produced no signal. An empty `peek` is INDISTINGUISHABLE from 'it was worked' — that ambiguity is the actual defect (id:4347 no-silent-swallow). MITIGATION THAT ALREADY EXISTS AND SHOULD BE NAMED IN THE FIX: the shard is NOT destroyed — it is preserved verbatim in `~/.config/relay/inject.done/<token>.json`, so recovery today is a manual move back into `inject.d/`. The gap is the absent signal + absent re-enqueue, not data loss. **(B) SCOPE-STEAL BY AN UNSCOPED POOL.** `inject.sh`'s own header records it: `--repo NAME` restricts `take`, and *'The pool passes its `--only` scope through discover-prelude.sh and the mid-round take; an UNSCOPED pool still drains globally (today's behaviour).'* So `--only` protects the SCOPED pool from stealing, but protects NOTHING from a parallel unscoped fleet pool, which drains every pending shard regardless of target repo. `--exclude` is strictly worse: excluded repos are dropped BEFORE sharding (no unit is ever emitted), so a fleet pool with `--exclude X` consumes X's injection and can then NEVER work it — a guaranteed loss. Parallel pools are the NORMAL case (id:11c6's singleton guard deliberately exempts `--afk` and every scoped/directed mode), so this is not a rare race. Prior instance cited in-file: run `relay-20260811-221031-22542`. **Fix directions (owner picks; do NOT guess):** (1) make `take` a LEASE rather than a consume — a unit not integrated by run-end returns to `inject.d/` (mirrors the claim.sh mtime-TTL model already in the codebase); (2) have the pool's exit path re-enqueue any taken-but-undispatched unit, and LOG every consume with its runId the way `id:cd94` made the STOP sentinel do; (3) make an unscoped `take` refuse shards whose repo is in the run's `--exclude` set at minimum. (1) and (2) address (A); (3) addresses (B); they are independent. Note the same steal-once shape was already fixed once for the STOP sentinel (`id:cd94`, run-scoped sentinel file) — that precedent is the design to mirror. <!-- id:10ff -->
