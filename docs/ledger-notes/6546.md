`TODO.md` / `ROADMAP.md` / `REVIEW_ME.md` item line is "really short, just lane, gate, id,

**The 460 split into four causes, and they do NOT share a fix:**

- **183 -- open, NO bold run.** The shrinker's cut rule needs a bold title to cut at, so it
  refuses these outright. This is the pre-registered D3/D4 composition gap (the founding
  meeting recorded 193 such items; 183 is the same population after wave 1). A refused line
  must never BLOCK, so today they simply stay long. **Needs a titling rule** -- the mechanical
  candidate is "first sentence or clause boundary, capped, remainder verbatim to the note",
  which truncates at a defensible boundary rather than inventing prose. That rule is the
  decision this item is gated on.
- **140 -- open, pointer already present, prose survived the cut.** The shrinker chose a cut
  point LATER than the title, so a parenthetical or a second bold run stayed on the line.
  Mechanical: tighten the cut to end-of-first-bold-run.
- **72 -- open, has a bold run, never shrunk.** Below the `--min-chars 500` threshold, so
  wave 1 never considered them. Mechanical: the strict shape has no length threshold, a
  400-char prose line is just as far from the bar as a 4,000-char one.
- **65 -- closed `[x]`.** The shrinker skips ticked items by design. This is nearly all of
  `ROADMAP.md`'s shortfall (which is why it reads 8% conforming while `TODO.md` reads 51%) --
  the file is mostly history. **Policy question, not a defect:** history is never dispatched
  and never sliced, so shrinking it buys bytes and nothing else.

**Do not start this before `id:30fe`.** The shape CHECK must exist first, or there is no
mechanical definition of "conforming" to shrink toward and no way to prove the wave landed --
the same reason wave 1's acceptance gate was built before the shrinker ran.

**Open sub-question the owner raised in the same breath:** whether the `-- detail:
docs/ledger-notes/<id>.md` pointer is "canonically redundant". It is derivable from the id, so
it costs ~40 chars on every shrunk line for zero information. Against dropping it: three
consumers key on the PATH being present (`ledger-slice.sh`'s `detail_collect`, `roadmap-lint`'s
`item_detail_path`, `ledger-shrink.py`'s own `has_pointer` idempotence guard), and file
existence is a different predicate from "this item HAS a relocated body". Decide it with
`id:30fe`, since the shape grammar has to name the pointer either way.
