# id:341e -- two independently-drifting "` M` with an empty diff is not real dirt" predicates, and they disagree

HAND-AUTHORED by relay review `relay-20260910-234645-16942` (2026-09-10). This note was NOT
produced by `tools/ledger-shrink.py`, so it carries no verbatim-reproduction claim.

## The two implementations

Both were written against the same measurement -- a git-annex repo with `annex.addunlocked`
where `git status --porcelain` reports ` M` forever because git never re-stats after annex
swaps in the real content, while `git diff` is empty.

**`relay/scripts/verify-isolation.sh` (id:3016), around line 213.** All-or-nothing: it builds
a `residue` of every porcelain entry whose XY pair is not exactly ` M`, and relaxes only when
that residue is EMPTY *and* `git diff --quiet` passes over the whole worktree. Any single
non-` M` entry, or any single genuinely-unstaged path, and every entry stays dirty.

**`relay/scripts/clean-tree-gate.sh` (id:8cc6), added 2026-09-10 in `23083671`.** Per-path:
one `git diff --name-only` for the repo, then a set subtraction -- each ` M` candidate whose
path is absent from that set is dropped as stat-cache dirt, and the rest still block.

## Where they disagree, concretely

A tree carrying 100 stat-cache paths plus **one** genuinely modified tracked file:

* `verify-isolation.sh` -- `git diff --quiet` fails, so `cosmetic_only` is 0 and it reports
  all 101 entries as a DIRTY tree.
* `clean-tree-gate.sh` -- 100 are subtracted, and it reports `dirty 1`.

Both gates run over relay repos in the same pipeline. Neither verdict is wrong on its own
terms; they simply answer different questions under one name, and a reader who has internalised
one will misread the other. Note also that the two differ in loudness: `verify-isolation.sh`
reads its porcelain with `2>/dev/null || true`, `clean-tree-gate.sh` deliberately does not and
fails closed with a message on stderr.

## Why this is a finding rather than an accepted duplication

`docs/ledger-notes/5239.md` -- id:8cc6's own detail note, written before the fix -- says it
outright, under "Prior art on this tree, read it first":

> `tests/test_verify_isolation_annex_cosmetic_3016.sh` already encodes a cosmetic-annex
> carve-out for the ISOLATION gate (`id:3016`). Reconcile with that predicate rather than
> writing a second, independently-drifting notion of "cosmetic annex entry" -- one predicate,
> two call sites, the `id:4d44` shape.

The shipped fix is excellent on its own merits and its own acceptance sketch is fully met
(hence id:8cc6 is closed), but it took the second branch: no `relay/scripts/lib-*.sh` owns the
predicate today, and `clean-tree-gate.sh`'s own comment records the duplication in passing
("`verify-isolation.sh` id:3016 records the same measurement independently").

## What "done" would look like

One `lib-statcache-dirt.sh`-shaped helper sourced by both call sites, exporting the per-path
answer, with each caller deciding its own all-or-nothing vs per-path policy EXPLICITLY rather
than by accident. Both existing specs -- `tests/test_verify_isolation_annex_cosmetic_3016.sh`
and `tests/test_clean_tree_gate_statcache_8cc6.sh` -- must stay green unchanged, and the
mixed-tree case above wants a new case pinning whichever policy each gate is meant to have.
