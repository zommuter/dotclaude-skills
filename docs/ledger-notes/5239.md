## Two distinct defects in one observation

Measured 2026-09-10 on `code.lawless`:

1. **Mislabelling.** The gate reported "93 uncommitted entries on the main checkout" while naming
   a WORKTREE. The main checkout `~/src/code.lawless` is `git status`-clean.
2. **Wrong predicate.** The 93 entries are git-annex symlinks that git-annex itself calls
   cosmetic -- restage/availability drift, not work. Counting them as uncommitted work would make
   the `id:aa93` dirty guard DEFER the repo **forever**: a self-perpetuating backlog, which is
   precisely the failure the dirty guard's own design note warns about.

## Why the pair matters rather than either half

Defect 1 alone is a misleading message; defect 2 alone is a false positive. Together they produce
a permanent, unactionable deferral whose message points the operator at a clean checkout -- the
"adjacent, authoritative-looking surface" class (`id:3f59`). A fix that corrects only the message
leaves the repo deferred; one that corrects only the predicate leaves the next annex repo's
operator reading about a checkout that is fine.

## Prior art on this tree, read it first

`tests/test_verify_isolation_annex_cosmetic_3016.sh` already encodes a cosmetic-annex carve-out
for the ISOLATION gate (`id:3016`). Reconcile with that predicate rather than writing a second,
independently-drifting notion of "cosmetic annex entry" -- one predicate, two call sites, the
`id:4d44` shape.

## Acceptance sketch

On an annex repo whose main checkout is clean and whose worktree carries only annex availability
drift, the gate PASSES and any message it prints names the path it actually inspected; a genuinely
dirty tracked edit in either location still fails. Pinned by a hermetic fixture (no real annex
content required).
