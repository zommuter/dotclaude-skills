## What was broken

`zom.fi` could not be registered in `relay.toml`. A dot is not a TOML bare-key character, so
neither spelling worked end to end:

* `[repos.zom.fi]` -- `tomllib` nests it as `repos/zom/fi`, the entry carries no
  `classification`, and `lib-own-repos.sh` drops the repo. SILENT: an empty own-set looks
  exactly like a clean fleet.
* `[repos."zom.fi"]` -- `tomllib` reads it correctly, but five scripts built the header by
  interpolating `[repos.$name]` and matched it as a fixed string, so none of them found the
  block. That direction fails INCONSISTENTLY, which is worse than failing uniformly:
  `relay-state-write.sh` refuses loudly, `ckpt-tag.sh` concludes the repo is unmanaged and
  skips the watermark sync, and `integrate.sh` reads `bump_policy` as ABSENT -- which is not
  neutral either, since absent takes the `id:65ad` fleet default and BUMPS.

## What shipped

* `relay/scripts/lib-repo-section.sh` is THE header renderer: `repo_section_header` (the
  canonical spelling we write) and `repo_section_headers` (every spelling TOML considers the
  same table, which is what a matcher must accept). Sourced by all five call sites rather than
  reimplemented. A bare-key name still renders bare, so all 63 existing entries are
  byte-identical and this is a no-op for them.
* `relay-state-write.sh` resolves the header to the spelling PRESENT IN THE FILE, not the
  canonical one -- otherwise the pre-check passes and `awk` appends the key at EOF instead of
  inside the block.
* Reader side: seven copies of the `# path:` comment-recovery regex captured the section name
  WITH its quote delimiters, so they never matched `tomllib`'s unquoted key and the override
  silently did not apply. Each now unquotes.
* Registered in the Makefile install manifest.

Leading-whitespace tolerance was deliberately left to each caller (`integrate.sh` trims,
`ckpt-tag.sh` does not); deciding it centrally would have silently widened two matchers that
were narrow on purpose.
