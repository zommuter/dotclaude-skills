### What I did

`tools/ledger-continuations.py` carried `REFUSE_IDS`, a hardcoded map of `id -> reason` for
items whose BODY is read by a live consumer, so relocating the body breaks it. It held one
entry, `id:6b35`. Once both of that item's consumers were re-anchored to the ledger+notes
union, the entry was correctly stale, and I emptied the dict.

**Emptying it did not just remove a stale entry -- it removed the MECHANISM.** `REFUSE_IDS`
*was* the cited-body check. With it empty, the tool's `REFUSED cited-body` counter now reports
`0` unconditionally, for every ledger, forever. It cannot report anything else.

That is a check that structurally cannot fail: the `id:0b70` vacuous-check class, and the
exact defect this session spent the day hunting elsewhere (`id:2d17`'s saturated detector,
`id:5f34`'s gate blind to a lost violation, `roadmap-lint`'s silent `return 0`). I removed a
guard and left its indicator in place still reporting success.

### Why it is not merely cosmetic

The hazard is real and fired TWICE on 2026-09-03, both times caught only by running the
suite, never by the counter:

- `roadmap-lint.sh:1039-1098` parses a hop table out of `ROADMAP.md`; relocating `id:6b35`'s
  body would have silently disarmed the SCOPE-TABLE-DRIFT check (`:1100` was
  `[[ -n "$reqs" ]] || return 0` -- no message, exit 0).
- `tests/test_contradiction_predicate_5533.sh` grepped `ROADMAP.md` for `id:931c`'s scoped
  `id:f599 is SUPERSEDED` wording; the `id:0d7c` shrink relocated it and the test went red.

Before applying the tool to `TODO.md` I hand-checked for consumers instead, and recorded the
method because the first attempt was itself bad evidence: probing for backticked tokens from
each body (`ROADMAP.md`, `--exclude`, `lodelore`) matched code for entirely unrelated reasons
-- a false-positive machine. The check that actually discriminates is narrow: find code that
reads a LIVE ledger path (`$ROOT/TODO.md`, `$ROOT/ROADMAP.md`) and greps its CONTENT. All
such readers today match ITEM LINES (`^- \[ \]`), none read continuation bodies, which is why
the `TODO.md` pass was safe.

**That hand-check does not survive me.** The next caller gets a green `cited-body: 0` and no
reason to look.

### What to build

Replace the hardcoded list with the check I ran by hand, mechanised. Sketch, not a spec:

1. Enumerate live-ledger readers: files matching the live ledger paths that also grep content.
2. For each candidate block, extract distinctive phrases and test whether any reader's pattern
   would match them.
3. REFUSE with the consumer's `file:line` in the message, the way the old entry did.

An id-keyed allow-list is the wrong shape regardless -- it says "this one is forgiven forever"
and goes stale silently, which is the `id:cb3e` grandfathering trap named in `id:0d7c`. The
predicate should be computed, not remembered.

**Interim, until it exists:** anyone running `ledger-continuations.py` or `ledger-shrink.py`
against a NEW corpus must do the reader check by hand and say so. Do NOT read
`cited-body: 0` as evidence of anything.
