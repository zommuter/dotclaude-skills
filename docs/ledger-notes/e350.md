# id:e350

Authored directly (not relocated by `tools/ledger-shrink.py`).

## From TODO

Found 2026-09-03 while arming the `id:2d17` shape ratchet. Four tests broke at once, none of
them related to the change under test.

### The defect class

`relay/scripts/todo-conformance.sh` defaults **both** ratchet baselines to committed files:

```
LENGTH_BASELINE="${LENGTH_BASELINE:-$SCRIPTS_DIR/../head-length-baseline.txt}"
SHAPE_BASELINE="${SHAPE_BASELINE:-$SCRIPTS_DIR/../shape-prose-baseline.txt}"
```

Both key on the ledger **basename**. Test fixtures are conventionally named `TODO.md` /
`ROADMAP.md`, so **a test that does not inject these reads the live repo's baseline** and its
verdict depends on repository state rather than on its fixture. That is not hermetic, and
`CLAUDE.md`'s Testing section requires hermeticity explicitly.

### Why it stayed invisible until now

The length ratchet's budget is **500 chars**, and most fixtures are short, so it almost never
fired on one -- the non-hermeticity was real but dormant from the day `id:0d7c` landed. The
shape ratchet fires at **8 chars of residue**, so it fired on essentially every fixture line
the moment a baseline existed, and the latent bug surfaced immediately.

**A fixture id absent from the committed baseline reports `shape-new`, which is an ERROR** --
so tests asserting `--strict` exits 0 failed for a reason with nothing to do with their
subject.

### The four, fixed in place (2026-09-03)

| test | what it actually tests | how it broke |
|---|---|---|
| `test_shape_check_30fe.sh` | the shape rule | expected class `shape-prose`, got `shape-new` |
| `test_dep_prose_untyped_gate_3f7e.sh` | DEP-PROSE-UNTYPED | fixture `cccc` -> `shape-new` -> `--strict` exit 1 |
| `test_state_claim_container_fp_bf19.sh` | the state-claim engine | same |
| `test_todo_conformance_length_ratchet_0d7c.sh` | the LENGTH ratchet | drives `LENGTH_BASELINE` deliberately, but not `SHAPE_BASELINE` |

Each now exports both baselines to absent paths under its own `mktemp -d`, keeping the
ratchets INERT -- which is the state their assertions already assumed.

### What is actually owed here

The four instances are fixed; **the class is not**. Nothing stops the next test that calls
`todo-conformance.sh` from omitting the injection, and it will pass until someone regenerates
a baseline -- the same dormancy that hid this one for weeks.

This is the mechanize-first case: the check is a pure function over test sources.

- **Acceptance**: a lint that flags any `tests/test_*.sh` invoking `todo-conformance.sh` (or
  `roadmap-lint.sh`, which shares the `lib-state-claim.sh` baseline design) without setting
  both `SHAPE_BASELINE` and `LENGTH_BASELINE`. Advisory first, matching
  `tests/lint-vacuous-fixtures.py`'s posture; escalate once clean.

  **Exempt** the two tests whose subject IS a baseline (`0d7c`, `2d17`, `cf64`) from the
  variable they legitimately drive -- but not from the other one, which is exactly how
  `0d7c` broke.

- **Done-check**: the lint reproduces all four findings against `88af3f44` (the commit before
  the fix) and reports clean against `main`.

### Broader note, not scoped here

Any check whose default points at a committed file inherits this shape. `lib-state-claim.sh`'s
`state-claim-baseline.txt` (`id:cb3e`) has the same design and is worth auditing the same way.
