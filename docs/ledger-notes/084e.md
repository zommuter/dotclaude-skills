## From TODO

— the id:a36e fix made `model:"bash"` work, but the proxy is reached via `ANTHROPIC_BASE_URL=127.0.0.1:…`, and that explicit base-URL override DISABLES `/remote-control` (the phone-push feature) — the client presumably keys remote-control registration/websocket off the standard endpoint or detects the non-standard base URL. IDEA (user 2026-07-23): instead of the env-var base-URL override, intercept TRANSPARENTLY at the network layer so the client still believes it is talking directly to `api.anthropic.com` and remote-control stays live, while the proxy still short-circuits `model:"bash"` and passes everything else through. Sketch: nftables/iptables DNAT (or `/etc/hosts` + a local :443 listener) redirecting `api.anthropic.com` to the local proxy, which TERMINATES TLS with a locally-trusted MITM cert (add a self-signed CA to the client/system trust store) and re-encrypts to the real upstream. FEASIBILITY/CAVEATS to weigh before building: (a) TLS interception needs a trusted cert in the store — more invasive than an env var; (b) it's self-MITM of your own machine's traffic (acceptable for own use, but note the trust-store change + the exfil surface — reconcile with id:f9cd proxy exfil hardening); (c) cert pinning in the client, if any, would defeat it — verify first; (d) confirm remote-control actually breaks on base-URL override (not some other cause) before investing.
