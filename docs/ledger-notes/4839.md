## The defect has three dimensions

All three live in `relay/scripts/todo-conformance.sh` and its two committed baselines
(`relay/head-length-baseline.txt`, `relay/shape-prose-baseline.txt`). Each is
separately verified.

### (a) The baselines are not installed -- ratchet INERT, but ANNOUNCED

The script resolves both baselines relative to itself:

```
LENGTH_BASELINE="${LENGTH_BASELINE:-$SCRIPTS_DIR/../head-length-baseline.txt}"
SHAPE_BASELINE="${SHAPE_BASELINE:-$SCRIPTS_DIR/../shape-prose-baseline.txt}"
```

The files live at `relay/head-length-baseline.txt` and `relay/shape-prose-baseline.txt`.
`relay_FILES` in the `Makefile` declares `SKILL.md` + `references/*` + `scripts/*` and
nothing else, so `make install` symlinks the script and never the baselines. Under
`~/.claude/skills/relay/scripts/`, `../head-length-baseline.txt` does not exist.

Measured on this worktree's own `TODO.md`:

| invocation | findings | warning |
|---|---|---|
| `bash relay/scripts/todo-conformance.sh TODO.md` | 1 | none |
| `bash ~/.claude/skills/relay/scripts/todo-conformance.sh TODO.md` | 216 | `head-length ratchet INERT -- no baseline` (+ the shape twin) |

Spot-check of the same source line (`TODO.md:989`): repo path reports
`shape-grandfathered (29 chars ... within baseline 29)`, install path reports
`shape-prose (29 chars ...)`.

This **fails OPEN**, not silent. The loss is the RATCHET SEMANTIC: with no baseline
there is no regrowth-versus-grandfathered distinction, so the 1 genuine regrowth is
indistinguishable from the 215 forgiven ones, and `id:0d7c`'s monotonic-shrink
guarantee is unavailable to exactly the callers built to enforce it -- `review.md`
section 4b and `relay-doctor.sh`, both of which prescribe the install path.

### (b) The baseline key has no repo dimension -- wrong ceiling, UNANNOUNCED

This is why (a) must not ship alone.

The baseline row format is `<ledger BASENAME>TAB<4-hex id>TAB<length in chars>`, and
the lookup key is built from it:

```
LENGTH_LEDGER_KEY="$(basename "$path")"          # :769
base="${LENGTH_BASELINE_MAP["$LENGTH_LEDGER_KEY/$id"]:-}"   # :725
base="${SHAPE_BASELINE_MAP["$LENGTH_LEDGER_KEY/$id"]:-}"    # :522
```

`relay/head-length-baseline.txt` holds 59 rows over 27 distinct ids, all of them ours.
Every repo in the fleet has a `TODO.md` and a `ROADMAP.md`, so the key
`ROADMAP.md/<id>` is satisfied by EITHER repo's item. The 4-hex id space is per-repo,
not fleet-unique, and the fleet has already adjudicated that fact: 187 recorded
cross-repo homonyms in `tracker/homonym-allowlist.txt`.

Demonstrated with token `55c7`, which is line 129 of that very allow-list:

- ours: `relay/head-length-baseline.txt:56` -> `ROADMAP.md	55c7	642` (em-dash migration S7)
- loderite's `ROADMAP.md` line for the same token is LONGER than our ceiling -> reported
  as ratchet **REGROWTH** against our 642 ceiling
- loderite's `TODO.md` twin is SHORTER -> silently **GRANDFATHERED** against that
  same entry

Both failure directions, one token, one baseline entry, no warning in either direction.

loderite cross-checked from their side and the failure runs OPPOSITE there: 335
findings via the repo path with NO warning, 267 via the install path WITH the INERT
warning -- because the repo path silently applies OUR baseline to THEIR corpus.

**So shipping the baselines through the manifest without adding a repo dimension
converts an ANNOUNCED INERT into an UNANNOUNCED WRONG on all 46 non-owning repos.**
The ratchet's key is missing a dimension this repo has already built an adjudication
file for.

### (c) The length metric is locale-dependent -- right ceiling, wrong number

Every measurement site uses bash `${#var}` (`:510`, `:512`, `:525`, `:526`, `:528`;
`:814` and `:876` for the regen writers). `${#var}` counts CHARACTERS under a UTF-8
locale and BYTES under `LC_ALL=C`.

Measured, one real ledger line: `LC_ALL=de_CH.UTF-8` -> 968, `LC_ALL=C` -> 986. 18
apart, from 8 non-ASCII characters. Re-measured here on `TODO.md:983`: 365 versus 367.

The baseline stores whatever the GENERATOR's locale produced and records no locale, so
a line within 18 chars of its ceiling flips between `shape-grandfathered` and
`shape-regrowth` on the invoking environment alone. This is not exotic: the fleet is
mid-em-dash-migration, so multibyte characters are pervasive on exactly the lines being
ratcheted.

**Pin the metric AT THE MEASUREMENT SITE, not only in the baseline format comment.**
The locale dependence originates in every ad-hoc measurement of these ledgers,
including the one deciding whether an item is a shrink CANDIDATE at all; the baseline
is merely where it persists. `tools/ledger-shrink.py`'s candidate gate uses Python
`len()` on a `str`, which is CHARACTERS -- so **chars is the metric to standardise on**,
and the shell sites must be made character-counting regardless of the invoking locale.

## Ordering is part of the acceptance, not a preference

A fix for any TWO of these ships the same failure by the third route:

- (a) without (b) is quietly authoritative with the wrong numbers on 46 repos.
- (a) + (b) without (c) is repo-correct and still environment-dependent.

If the full fix will not fit one unit, split it -- **but the manifest change must NOT
land first.** Loudly inert everywhere beats quietly authoritative.

## Two aggravations, fixed in the same pass

1. `relay/scripts/relay-doctor.sh:298` invokes `todo-conformance.sh` with `2>>"$LOG"`,
   so BOTH INERT warnings never reach the reviewer reading its output. That is why
   this went unnoticed.
2. `relay-doctor`'s own `install-drift` check walks `scripts/*` + `references/*` only,
   so it **structurally cannot see** a manifest gap in a non-script file -- the guard
   is blind to the exact class of gap that disabled it.

## Acceptance

All of the following, in one landed state:

1. **Repo dimension in the key.** Both baselines carry a repo dimension and the lookup
   uses it, so a row minted in repo X can never supply a ceiling for repo Y. A lookup
   that finds no row for the invoking repo behaves as "not baselined" for that repo,
   loudly and by the existing `-new` classes -- never by silently borrowing another
   repo's row. Legacy rows in the old two-column-key spelling are REFUSED loudly (or
   migrated by an explicit, tested act), never read as if they were this repo's.
2. **Locale pinned at every measurement site.** Every length/residue measurement in
   `todo-conformance.sh` (`:510`, `:512`, `:525`, `:526`, `:528`, `:814`, `:876`)
   counts CHARACTERS and returns the same number under `LC_ALL=C` and under
   `LC_ALL=de_CH.UTF-8`, matching `tools/ledger-shrink.py`'s Python `len()`. The
   baselines record the metric so a future reader cannot re-introduce the ambiguity.
3. **Baselines installed.** `relay_FILES` ships both baseline files, and
   `bash ~/.claude/skills/relay/scripts/todo-conformance.sh TODO.md` no longer prints
   either INERT warning and agrees, finding-for-finding, with the repo-path invocation
   on this repo's `TODO.md` and `ROADMAP.md`.
4. **Ordering enforced by the change itself**, not by a note: the manifest line from
   (3) may not be in a state where it is live while (1) is not. A landed (3) without a
   landed (1) is a regression and the tests must say so.
5. **Aggravation 1**: `relay-doctor.sh`'s `todo-conformance` invocation surfaces the
   INERT warnings (and any future stderr from that tool) to its own output, not only
   to `$LOG`.
6. **Aggravation 2**: `relay-doctor`'s `install-drift` walk covers every path declared
   in `relay_FILES`, not just `scripts/*` + `references/*`, so a missing non-script
   file is reported.

## DIMENSION (b) -- derive REPO_KEY from `--git-common-dir`, NOT `--show-toplevel` (2026-09-08)

(This note has been edited since authoring, per `docs/ledger-notes/README.md`.)

An attempt at the repo-keyed baseline was made by a pool child that died mid-task
(`relay/orphan/relay-20260908-174448-4421-execute-c655-0`, DISCARDED). Its analysis is
banked here so the re-do does not rediscover the defect.

**The baselines themselves were CLEAN -- this is worth recording, because it was the
suspicion that prompted the review.** Diffed key-by-key with the repo column stripped:
`head-length-baseline.txt` 27 rows, `shape-prose-baseline.txt` 240 rows, **0 values
loosened, 0 tightened, 0 keys added, 0 keys dropped**. A pure format migration, not a
re-snapshot. The `id:0d7c`/`id:cb3e` re-grandfathering hazard did NOT fire.

**The defect is the key derivation.** The branch used:

```bash
REPO_KEY="$(basename "$(cd "$(dirname "$path")" && git rev-parse --show-toplevel 2>/dev/null || pwd)")"
```

In a linked worktree `--show-toplevel` returns the WORKTREE path, so `REPO_KEY` becomes
`agent-af857798f9b6745c6` or `relay-20260908-174448-4421-execute-aa5e-0` -- never
`dotclaude-skills`. **That is where every relay executor runs.** Measured on an identical
`TODO.md` in the same worktree:

| class | `main` | with the branch |
|---|---|---|
| shape-grandfathered | 213 | **0** |
| shape-new | 26 | **239** |
| length-grandfathered | 8 | **0** |
| length-over-budget | 14 | **22** |

**The failure direction is spuriously STRICT, which is why it is dangerous rather than
merely wrong.** 213 grandfathered items reappear as `shape-new`, which the script's own
header calls an ERROR that fails `--strict`. The remedy an operator reaches for under 239
red findings is `--regen-shape-baseline` from inside the worktree -- which writes
`agent-xxxx` keys that can never match the real repo again. That is permanent
re-grandfathering arriving through the back door, i.e. exactly the hazard `id:0d7c` names,
reached by a route no one was watching.

**Use `git rev-parse --git-common-dir` (or `--path-format=absolute --git-common-dir`)**, which
resolves to the MAIN checkout's git dir from inside a linked worktree, and derive the repo
name from that. The branch's in-code comment claimed the derivation was checkout-correct
("so `todo-conformance.sh /some/other/repo/ROADMAP.md` from anywhere still keys correctly") --
true for the cross-repo case, false for worktrees, and unverified either way. Any re-do
should carry a test that runs the checker FROM a linked worktree, since that is the only
place the bug appears and no existing fixture does it.

Other residue defects in that branch, for completeness: it added a `repo_key_for()` helper to
`tests/test_todo_conformance_length_ratchet_0d7c.sh` and never called it (`grep -c` = 2, the
comment and the definition), leaving the fixture rows 3-column so they tripped its own new
"refuse legacy 3-column row" `exit 2`; and it regressed two tests that are green on `main`
(`test_todo_conformance_length_ratchet_0d7c.sh`, `test_shrink_acceptance_signal_identity_75c8.sh`).
One `roadmap:4839` red spec (`test_conformance_baseline_repo_key_4839`) DID go green, so the
idea is sound -- it is the execution that was caught mid-task.
