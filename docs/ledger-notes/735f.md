## From TODO

Filed 2026-09-04 after TWO tests flaked in one session. Filed rather than closed as
"passed on retry", because a definition-of-done check that fails intermittently is worse
than one that fails: it teaches the operator to re-run until green, which is how a real
regression gets waved through.

### The two instances, both measured

| test | standalone | in a loaded parallel run |
|---|---|---|
| `tests/test_privacy_gate_prepush.sh` | PASS, 17 ok / 0 bad | FAILED once |
| `tests/test_verdict_event_c7dc.sh` | PASS, 8/8 | FAILED once, at `(B2) ... missing the 'verdict' field` |

Both green on re-run (`575 passed, 0 failed`). Neither is explained.

For `c7dc` the failure is provably NOT a content problem: `relay/scripts/relay-loop.js` was
byte-identical to `HEAD` throughout, the test resolves its own root from `BASH_SOURCE` so it
cannot drift onto a worktree copy, `(B1)` passed on the same blob that `(B2)` then failed on,
and the blob plainly carries `verdict:` on three lines. The assertion was false about a fact
that was true.

### A hypothesis TESTED AND REFUTED, recorded so nobody re-runs it

`printf '%s' "$vcall" | grep -Eq ...` under `set -euo pipefail`: `grep -q` exits on first
match, `printf` takes SIGPIPE, and `pipefail` turns that into a failed pipeline. That shape IS
present in the file, and it is a known class here (`id:81d5`) with its own lint.

**It does not hold.** `tests/test_pipefail_sigpipe_lint.sh` reports the repo free of the banned
shape with zero exemptions, and a 10-iteration reproduction of the exact pipeline passed 10/10.
Do not re-derive this; it was checked.

### The generalizable defect, which is the reason this is worth an item

**A test that ends an assertion with `|| fail` cannot distinguish "the assertion is FALSE" from
"the check COULD NOT RUN".** `grep` exits 1 for no-match and **2 for an error** -- a missing
file, a permission problem, a failed fork or allocation under load. Both are non-zero, so both
take the `|| fail` branch and both report as a failed assertion.

**360 test files use `|| fail` after a grep.** Under a parallel runner on a machine that has
been at load average up to 29 with 30 registered worktrees, a transient subprocess failure is
not exotic, and every one of those sites would report it as a substantive test failure naming
a property that is actually fine.

This is the familiar vacuous-check family running in the OTHER direction. `id:0b70` and
`id:9ce0` are about a check that cannot fail; this is a check that cannot tell WHY it failed,
and so produces a false RED. A false red is cheaper than a false green, but it is not free: it
is what trains an operator to re-run, and the re-run habit is what makes a true red invisible.

### What to build

1. Distinguish `grep`'s exit 1 from exit 2 or higher at the assertion sites, so an ERROR is
   reported as an ERROR (loudly, naming the failing command) and never as a false assertion.
   360 sites means this wants a shared helper rather than 360 edits -- the `id:4983`
   one-definition shape.
2. Make the runner report a test that failed with a distinguishable execution error separately
   from one whose assertion was false, so an operator can see the difference in the summary
   rather than by opening the log.
3. **Do NOT add a blanket retry.** Retrying a flaky check hides exactly the signal this item
   exists to preserve. If a retry is wanted at all, it must report that it retried and why.

The mechanism behind these two specific flakes is still UNKNOWN, and this item does not claim
to have found it. It fixes the property that made the flake unreadable.

- **Acceptance**: an assertion whose check could not EXECUTE is reported as an execution error
  naming the command and its exit status, distinctly from a false assertion; the distinction
  is visible in the runner summary; and no blanket retry is introduced.

- **Done-check**: a fixture whose `grep` targets an unreadable path reports an ERROR rather
  than a failed assertion, and the runner summary shows it in its own category; a fixture whose
  assertion is genuinely false still reports as a failure.
