# id:60eb

Authored directly (not relocated by `tools/ledger-shrink.py`).

## From ROADMAP

Two rules in the same file disagree about what a detail pointer is.

`relay/scripts/todo-conformance.sh`'s `grammar_item_class` (`id:b048`) strips the lane tag
and the trailing marker run before measuring title length, but it does NOT strip the
`-- detail: <path>` pointer. `shape-prose` (`id:30fe`), in the same script, explicitly
excludes "lane/gate/id/title/**pointer**". So the pointer is chrome to one rule and title
text to the other.

### Why it is not cosmetic

The `id:0d7c` topology REQUIRES a pointer on any item whose body was relocated, and
`roadmap-lint.sh` rule 3(c) (`id:e95b`) reports `DETAIL-POINTER-MISSING` when it is
absent. So the grammar penalises an item for satisfying a different rule that another
detector enforces. Planting a mandatory pointer can push a conforming item over the title
budget with no prose added at all.

OBSERVED, not hypothetical: the `id:40c0` migration (commit `39146fc7`) planted 18
pointers and `grammar-item-title-long` went 5 -> 6 while `length-over-budget` went
11 -> 12, both on `id:7408` and `id:372a`, purely from the pointer. The migrating agent
took the pointer over the budget deliberately, which was the right call -- omitting it
makes the note unreachable -- and reported the trade rather than hiding it.

### Fix

Teach `grammar_item_class` to strip the detail pointer before measuring, the way
`shape-prose` already does. Prefer sharing one helper over a second spelling of the
pointer pattern: two copies drift, and drift here is silent.

### Watch for

This also affects `id:64f9` (the 257 over-long titles). Any title measurement taken
before this fix over-counts every item carrying a pointer, so the 257 figure is an upper
bound and should be re-measured after the fix rather than carried forward.
