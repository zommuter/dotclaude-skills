## From TODO

### The measurement

Relocating 34 items' prose into `docs/ledger-notes/` under the ratified `id:0d7c` format:

| | before | after | delta |
|---|---|---|---|
| `TODO.md` | 202,914 | 196,222 | **-6,692** |
| 34 new note files | -- | 33,691 | **+33,691** |
| `classify-repo.sh` `todo_bytes` | 1,950,398 | 1,977,325 | **+26,927** |

Of the 33,691 note bytes, **24,514 are generated boilerplate header** (721 bytes average per
note) and only **9,105** are the relocated prose.

**So the pass moved ~9 KB of text and paid ~24.5 KB of header, and the byte gate counts all
of it.**

### Why it counts, and why that is not a bug

`relay/scripts/classify-repo.sh:216` computes
`todo_bytes = getsize(TODO.md) + _ledger_note_bytes(TODO.md)` -- the pointed-to notes are
counted IN, deliberately. That is `id:f3d2`, and it was ratified for a good reason: a gate
that counted only the ledger would go optimistic the moment prose moved behind a pointer,
disarming the guard against the very failure `id:0d7c` was filed for (a relay child dying
with `Prompt is too long`). `f3d2` exists so relocation cannot buy a false green.

The consequence is that the format's two goals now pull in opposite directions:

- **Line LENGTH improves**, which is what the `id:0d7c` ratchet actually targets, and what
  makes a single `grep` hit cheap instead of returning 7k tokens.
- **Total BYTES get worse**, at roughly 721 bytes per item, because every note carries a
  full header.

### Why it is worth a decision NOW rather than later

`id:03a3` migrates 46 repos. At ~721 bytes of header per relocated item this is the largest
single application of the format so far, and the scaling property has not been priced. A
fleet migration that improves every line length while adding tens of thousands of bytes to
each repo's `todo_bytes` is a defensible trade -- but it should be a CHOSEN one, and today it
is a side effect nobody has looked at.

### Options, none free, none recommended here

1. **Accept it.** Line length is the real target; the byte gate's job is to refuse an
   over-large prompt, and a note that is never opened costs nothing at dispatch. Requires
   confirming that `_ledger_note_bytes` is measuring what the gate actually cares about.
2. **Shrink the header.** 721 bytes is mostly a standing explanation of the notes-are-editable
   convention and the verbatim claim. It could be one line plus a pointer to the convention.
   Cheapest lever by far, and it does not touch the format.
3. **Stop counting note bytes**, or count them differently (e.g. only for notes a prompt
   actually inlines). This REOPENS `id:f3d2`, which exists precisely to stop this, so it
   needs that item's argument answered rather than ignored.

**Do not read this note as a recommendation.** The measurement is the contribution; the
trade is the owner's.

### DECIDED 2026-09-04 -- OPTION 2, shrink the header

**Owner-ratified.** The byte gate's treatment of note headers STANDS as ratified: `id:f3d2`
is not reopened, `_ledger_note_bytes` keeps counting notes IN, and the format itself does not
change. The lever is the header alone.

**Per-item header cost measured AT THE TIME OF THE DECISION**, as the done-check requires,
because this note's 721 was the 34-item pass average and has moved:

| | measured 2026-09-04 |
|---|---|
| notes on disk | **779** |
| total header bytes | **387,292** |
| **average header** | **497 B/note** |
| total note bytes | 2,229,463 |
| headers as a share of notes | **17.4%** |

**New header shape**: one provenance line plus a pointer to `docs/ledger-notes/README.md`,
which now carries the standing explanation for all notes at once.

**The verbatim claim is LOAD-BEARING and is therefore RELOCATED, never deleted.** It moves to
`README.md` as a DEFAULT that every generated header incorporates by reference, defeasible BY
EXCEPTION: a note whose prose was edited since relocation declares that in its OWN header, and
that declaration overrides the default. This preserves the property the 2026-09-02
notes-are-editable ruling depends on -- the note stays honest about itself -- while paying for
it once in a shared file instead of 779 times.
