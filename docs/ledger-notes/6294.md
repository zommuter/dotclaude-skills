**Mechanism, traced to the exact line pair rather than inferred.** Block (3) of the
test, at `tests/test_privacy_gate_prepush.sh:114`, runs

```
out="$( ( cd "$REPO" && printf '%s\n' "$STDIN_LINE" | \
    PRIVACY_GATE_PATTERNS="$TMP/does-not-exist.txt" ... bash "$HOOK" ... ) 2>&1 )"; rc=$?
```

with the pattern file deliberately absent. `hooks/pre-push-privacy-gate.sh` takes its
D4 absent-pattern-file `exit 0` at `:48`, which is **before** its
`while IFS= read -r line` at `:54`. The hook therefore never drains stdin, `printf`
dies of SIGPIPE (141), `set -o pipefail` promotes 141 to the pipeline's status, and
the assignment inherits it under `set -e`.

**This does NOT weaken the id:81d5 mechanism -- it widens its population.** The lint
`tests/lint-pipefail-sigpipe.py` states in its own docstring that it flags only a
"KNOWN-early-exiting consumer", and its classifier enumerates `grep -q/-m/-l`,
`head`, `sed Nq` and `awk ... exit`. A shell script invoked as
`producer | bash <script>` is not in that set, so the 427-site / 162-file sweep
id:81d5 measured could not have counted these. For `id:7518` clause 4 this is a
**CONFIRM** observation for the SIGPIPE hypothesis, not a kill: the failure shape
(assertion demonstrably true, pipeline status lying) is the same self-proving shape
as the banked `test_integrate_sh_mechanized.sh` and `test_gaming_scan.sh`
reproductions. It is also the first recorded flaker in a file that used to be
**masked** -- `test_privacy_gate_prepush.sh` is one of the three files the
2026-08-22 review named as maskable, and its `# roadmap:ebd0` item is now `[x]` in
`ROADMAP.archive.md`, so the flake that was invisible to the green/red signal now
fails the suite. That is the id:86ca prediction arriving.

**Second, independent defect on the same line, and it is why the failure is silent.**
The test writes `out="$(...)"; rc=$?` intending to capture the hook's exit code, but a
simple assignment whose right-hand side is a command substitution takes that
substitution's status and is not in a `set -e` condition context. The shell exits
before `rc=$?` is ever read, so the `[[ $rc -eq 0 ]] || bad ...` guard the author
wrote can never report anything. Seven sites in that file share the
`printf ... | bash "$HOOK"` shape.

**Acceptance**

1. `tests/lint-pipefail-sigpipe.py` classifies a pipeline whose consumer is an
   invocation of a script under this tree as at-risk unless that script provably
   drains stdin -- or, if proving that is out of reach, flags `| bash <path>` /
   `| sh <path>` as at-risk outright and the rewrite is applied at the call sites.
   Whichever branch is taken is stated in the commit, since they differ in false-positive
   cost and that is the reviewer-visible trade.
2. `tests/test_privacy_gate_prepush.sh`'s seven `printf ... | bash "$HOOK"` sites use
   a non-pipe producer form (`< <(printf ...)` or a heredoc), so a hook that exits
   early cannot SIGPIPE them.
3. A regression test pins that a script-consumer pipeline is reported by the lint.
4. The `out="$(...)"; rc=$?` sites are rewritten so a non-zero hook status is
   actually reportable by the guard that was written for it.
