## From TODO

**`verify-isolation.sh` declares a git-annex worktree DIRTY on cosmetic pointer-file noise, so
the isolation gate hands back every execute round on an annex repo.**

**The mechanism, read from the source.** `relay/scripts/verify-isolation.sh:190`:

```bash
porcelain="$(git -C "$worktree" status --porcelain 2>/dev/null || true)"
if [ -n "$porcelain" ]; then
  echo "isolation failure: worktree has a DIRTY tree (uncommitted changes) — not safe to merge"
```

ANY porcelain output is treated as dirty. There is no `git diff` cross-check. On a git-annex
repo, unlocked pointer files report ` M` in `git status --porcelain` while `git diff` is EMPTY
-- annex's own position is that this is cosmetic, and it names `git-annex restage` as the
remedy. So the gate fires on a worktree that has no real modification, refuses the merge, and
the unit hands back. Reported live on `code.lawless` and `zkWhale`, both confirmed annex repos
(`.git/annex` present).

**This exact class was already fixed ONCE, next door.** `id:de4a` (closed 2026-07-16,
`TODO.archive.md:395`) fixed *"git-annex worktrees can NEVER be retired -- `worktree-retire.sh`
refuses forever and misreports it as dirty"*, with the root cause proven empirically: the
`.git` symlink appears immediately at `git worktree add` via `filter.annex.process`, the smudge
filter -- NOT the annex `post-checkout` hook, a hypothesis that was tested and DISPROVED. The
inbound report is right that de4a covers only the `.git`-symlink half; the unlocked-pointer
half was never carried across to the sibling gate. `verify-isolation.sh` mentions annex only in
a comment about BRANCH resolution (`:84-85`); its dirty path has no annex awareness at all.

**Suggested fix (from the reporter, and it looks right):** confirm with `git diff` before
declaring dirty -- porcelain non-empty AND a non-empty diff -- or run `git-annex restage`
first. Prefer the diff-confirm: it needs no annex binary, it is correct on non-annex repos
(where porcelain-without-diff essentially cannot happen for tracked content), and it keeps the
gate's fail-safe direction. Note `git status --porcelain` also reports UNTRACKED files, which
`git diff` never shows, so a naive "require a non-empty diff" would blind the gate to genuine
untracked residue: the predicate must keep treating untracked entries as dirty and relax ONLY
the modified-with-empty-diff case.

**What was verified from the code here.** The `:190` predicate as quoted; that `zkWhale` and
`code.lawless` carry `.git/annex`; that `verify-isolation.sh` has no annex handling in its
dirty path; and that `id:de4a` set the precedent in the sibling script.

## REPRODUCED 2026-09-09 -- observed live, with one stated confound

Supplied by the reporting session (run `relay-20260909-115705-28382`, execute unit for
`id:6df0`), worktree
`~/.cache/relay/worktrees/code.lawless/relay-20260909-115705-28382-execute-repo-0`. It
happened BEFORE this note was written, so nothing here was staged for the purpose:

1. The pool's integrate step got `handbackCode=21` from `verify-isolation.sh`, naming **77**
   modified paths, all under `docs/research/img/`.
2. `git status --porcelain | wc -l` → **77**, every entry ` M`, **no untracked**.
3. `git diff --stat` → **0 lines**. `git diff HEAD --raw -- <one .png>` → empty.
4. The index blob for that file is **99 bytes** (an annex pointer); the working file is **5297
   bytes** (a real PNG). Both the main checkout and the worktree hold the 5297-byte regular
   file with the same mtime. `annex.addunlocked true`, annex repo version 10.
5. `git update-index --refresh` did **NOT** clear it -- still 77. Worth recording: the cheap
   fix someone will reach for first does not work.
6. git-annex itself printed, per file, on **stderr**: *"git status will show <path> to be
   modified, since content availability has changed and git-annex was unable to update the
   index. This is only a cosmetic problem affecting git status; git add, git commit, etc won't
   be affected. To fix the git status display, you can run: git-annex restage"*.
7. `git annex restage` → `restage ok`; porcelain → **0**; `git worktree remove` then succeeded.

**CONFOUND, stated by the reporter unprompted and preserved here.** A `--discard-residue` ran
between steps 2 and 7, so it is **NOT established that `restage` alone would have cleared the
original 77**. What is uncontaminated is steps 2-6: porcelain-77 with an empty diff, `refresh`
failing to clear it, and annex's own diagnosis naming `restage`. That is already enough to
establish the defect; the restage-as-remedy step is the part still owed a clean run.

**BOTH HALVES FIRE ON THE SAME WORKTREE, IN SEQUENCE -- so `id:de4a` is necessary but NOT
sufficient.** `worktree-retire.sh` first failed with `'.git' is not a .git file, error code 10`
(the de4a half); once that was normalised, the NEXT invocation failed with `contains modified
or untracked files` (this half). An annex worktree needs both fixes to be retirable at all.
That is the strongest argument against treating this as a duplicate of de4a.

**A THIRD wrinkle, not yet explained and deliberately not folded into this item.** Immediately
after the discard, `status --porcelain` read **0** while `git worktree remove` still judged the
tree dirty -- git's own worktree-remove validation and porcelain disagreed at that moment. That
is a different predicate disagreeing with a different predicate, on the same tree, and it is
not what this item fixes. Investigate separately before assuming the diff-confirm predicate
below would have helped it.

The reporting session **accepted the untracked correction** ("you are right and I was wrong ...
relaxing only the modified-with-empty-diff case, keeping untracked dirty, is the correct
predicate"), so the acceptance below is agreed across both sessions rather than asserted by
one.

**Acceptance:** a fresh worktree of an annex repo with only unlocked-pointer noise passes the
isolation gate, while a worktree with a real uncommitted modification OR untracked residue
still fails it. **Done-check:** a hermetic fixture covering all three cases; `make test` green.
The reproduction above gives the fixture its shape: ` M` entries whose `git diff` is empty and
whose index blob is an annex pointer, with `update-index --refresh` deliberately NOT part of
the remedy path since it was measured not to work.
