# id:36bc -- `relay-doctor`'s mechanical-orphan detector substring-matches `[MECHANICAL]`, so gate PROSE manufactures false orphans

Inbound `routed:5816` from an `ai-codebench` relay review, 2026-09-10. Reported with a line cite and
a measured count; ingested as reported and **not independently re-measured here** (noted so the next
reader knows which parts are verified).

## The mechanism as reported

`relay/scripts/relay-doctor.sh:474` tests `if "[MECHANICAL]" not in line`, i.e. an unanchored
substring match anywhere in a ROADMAP line. A line whose GATE PROSE mentions the lane -- e.g.
"re-lane to `[MECHANICAL]` + A2 recipe" -- therefore reads as a `[MECHANICAL]` item even though its
actual leading lane tag is something else entirely.

Measured in `ai-codebench`: **4 false positives** (`bde7`, `fadb`, `8c1d`, `3ee7`), all of which are
really laned `[INPUT - decision]`.

## Why it matters beyond a noisy report

`mechanical-orphan-draft.sh` consumes this detector. A false orphan there would manufacture a
STRANDED DRAFT -- a recipe for an item that is not mechanical work and cannot be run by the
mechanical daemon. So the cost is not just four wrong lines in a health report; it is the draft
generator acting on them.

## The fix, and it already exists elsewhere in this repo

Anchor the test to the LEADING lane run, exactly as the lane-tag readers do. This repo has solved
the same problem more than once: `tools/ledger-shrink.py` anchors on `primary_lane()` /
`leading_lane_run`, and `hooks/pre-commit-lane-vocab.sh` extracts the first lane tag via
`first_lane_tag` after matching a checkbox prefix. Reuse one of those predicates rather than writing
a third.

This is the same family as the `[GATED]` substring false-positive already filed as `id:259f`
(`gated?` with no word boundary matching *investigate* / *mitigate* / *aggregate*), and the same
family as `id:aa0d` found in the same pool run. Three instances of "a lane/gate token matched as a
bare substring instead of in its grammatical position" argues for ONE shared predicate that every
consumer calls, not three independent anchorings -- worth considering when fixing this.

## Acceptance

* A ROADMAP line whose PROSE mentions `[MECHANICAL]` while its leading lane is something else is NOT
  reported as a mechanical orphan.
* The 4 named `ai-codebench` items stop being reported.
* A genuine `[MECHANICAL]` item is still detected (regression guard).
* `mechanical-orphan-draft.sh` is re-checked against the corrected detector before it is next run,
  since a stranded draft is the real cost.
