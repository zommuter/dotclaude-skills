`git worktree add` gives a relay child an empty tree for everything gitignored, so any repo with an expensive derived cache makes every child pay a full cold rebuild. Concrete measured case (lodelore, 2026-08-10): `lean/.lake` is **1.9 GB** of Mathlib; `~/src` and `~/.cache` are both btrfs on the same device (`/dev/nvme0n1p2[/@home]`), so `cp --reflink=auto -a <main>/lean/.lake <worktree>/lean/.lake` is near-instant and near-zero space, versus a cold `lake exe cache get` + build per child. GENERALISES well beyond Lean — `node_modules`, uv/venv trees, Rust `target/`, model/index caches — which is why the hook belongs in relay's worktree-creation path rather than in each repo's own scripts. SHAPE: after `git worktree add`, if `<repo>/.relay-worktree-seed.sh` (or a `relay.toml` key) exists, run it with the worktree path; repos without one are unaffected. GUARDS THAT MATTER: `--reflink=always` FAILS on non-CoW filesystems while `--reflink=auto` SILENTLY degrades to a real full copy — for a 1.9 GB cache that is worse than doing nothing, so the hook must detect same-filesystem + CoW support and skip loudly otherwise, never silently duplicate. And **a reflink is a SNAPSHOT, not a live link** (recorded lens, mathematical-writing 2026-07-10 lean-toolchain-pin-ownership): a seeded cache goes stale when the pin moves, so the contract must be "seed, then let the repo's own freshness check re-derive", never "seed and assume fresh".
