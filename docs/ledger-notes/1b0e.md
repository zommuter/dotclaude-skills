## From ROADMAP

**`workflow_node_check` returns 0 -- a PASS -- on a file it could not read.** Found
2026-09-08 by the `id:62c9` review, probing the helper with its own fixtures rather than the
spec's. This is the silent-pass class the item's own acceptance bans, reached through a door
the acceptance did not name.

**Measured, reproducibly, on the landed `tests/lib-workflow-check.sh`:**

```
$ printf 'const a = ;\nthis is not javascript at all {{{\n' > broken.js
$ workflow_node_check broken.js >/dev/null 2>&1 ; echo $?
1                      # readable, genuinely broken -> caught, correct
$ chmod 000 broken.js
$ workflow_node_check broken.js ; echo $?
awk: fatal: cannot open file `broken.js' for reading: Permission denied
sed: can't read broken.js: Permission denied
0                      # SAME FILE, unreadable -> PASS
```

**The mechanism.** `[[ ! -f "$f" ]]` guards existence but not readability. The refusal scan
then runs `awk ... "$f"` inside a command substitution: awk dies, stdout is empty, so
`bad_line` is empty and reads as "no unmodellable construct found". The wrapper build is a
brace group whose exit status is the LAST command's (`printf '\n}\n'`, always 0), so `sed`'s
failure is discarded too. The temp file ends up holding only
`async function __relay_wf__(){ ` + `}` -- an empty async function, which `node --check`
parses happily. Every stage failed; the function returned success.

**Why the loud stderr does not save it.** Roughly 40 of the 48 migrated call sites invoke the
helper as `workflow_node_check "$JS" >/dev/null 2>&1 || fail ...`, so the awk/sed diagnostics
are discarded at the call site and the operator sees a green test. That is precisely the
`no-swallow-stderr` / `id:4347` no-silent-swallow shape.

**Reachability, stated honestly.** Low in the normal suite: the tests run as the owner over
files the owner owns. The class is wider than the permission case, though -- any read failure
reaches it (an I/O error, a path whose permissions changed under a long run, a file removed
between the `-f` probe and the read). The severity is not the frequency; it is that the one
outcome this helper exists to make impossible -- a broken `relay-loop.js` reported green
across 47 guards -- has an unguarded path to it.

**Not a defect in `id:62c9`'s acceptance.** That acceptance scoped "no silent pass" to the
unmodellable-module-scope clause, and the helper honours it there. This is residue the review
found beside it, so `id:62c9` stays ticked.

**Acceptance**: `workflow_node_check` exits non-zero, with a message naming the file, when
the file cannot be read -- demonstrated on a `chmod 000` fixture, not merely by inspection.
The wrapper build must also not treat a failed `sed` as success: check it, or verify the
written temp file is at least as long as the source. **Done-check**: a new assertion block in
`tests/test_workflow_node_check_62c9.sh` covering the unreadable case, plus full
`tests/run-tests.sh` green.

**Context**: `tests/lib-workflow-check.sh` (the `[[ ! -f ]]` guard, the `awk` refusal scan,
and the `{ printf; sed; printf; } > "$tmp"` brace group).
