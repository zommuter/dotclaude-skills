(owner request 2026-08-26) — `tools/claude-relay.sh` currently `exec`s Claude directly in the calling terminal, so a long unattended run (`/relay --afk`, a chaining pool) dies with the terminal: closing the window, an SSH drop, or a laptop suspend kills the session and every in-flight child, parking their worktrees as `relay/orphan/*`. This is the same exposure the id:bde8 scope correction names — `/loop` retries early-exits but **dies with the session** — and the gap id:98f0's outage watchdog only *reports* after the fact. Wrapping the launcher in tmux makes the session survive the terminal and lets the owner reattach. Shape: if `$TMUX` is unset (not already inside tmux) AND `tmux` is on PATH, launch via `tmux new-session -A -s <name>` so a re-invocation ATTACHES to the existing session rather than starting a second Claude; if already inside tmux, or tmux is absent, run exactly as today (never nest, never hard-fail). Decide: the session name (fixed vs per-cwd — per-cwd avoids two repos fighting over one session), whether the proxy-healthy and proxy-direct branches both wrap, and whether an opt-out env var is wanted (the launcher is opt-in by design, id:e905).
