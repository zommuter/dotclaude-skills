The item ended with a binary: *"Decide: mint id markers onto checkbox lines fleet-wide, or give
md-merge a REVIEW_ME-shaped anchor."* Neither was chosen. A **third** shape shipped:
`relay/scripts/review-box-tick.py` (`ee0b17ed`), a composer that uses the anchor
`update-sections` ALREADY has -- the enclosing `## ` heading -- and takes over the part that was
actually dangerous, hand-composing the section replacement, which is where a wrong box gets

It extracts the section verbatim, flips exactly one checkbox, emits the caller's rationale as
its own paragraph at the END of the box, and hands the section back to `meeting/md-merge.py
update-sections` under that tool's flock. It never writes a ledger itself: with md-merge
unavailable it writes nothing, and there is no fallback path.

`relay/SKILL.md` 3(a) now mandates it and forbids `Edit`, which bypasses the flock exactly as
`sed -i` does. The Makefile ships it in all three relay manifests (`relay_FILES`, `relay_EXEC`,
`relay_ALLOW`), so `make install` symlinks and allowlists it rather than leaving it inert.

## The defect found on first use, and why its fix is the interesting part

`c9a24cf5`: the first version appended the rationale to the CHECKBOX LINE. A REVIEW_ME head
line is a PHYSICAL line, not a semantically complete unit -- measured that day, **188 of 431**
open boxes fleet-wide have a title that WRAPS, including this repo's own `REVIEW_ME.md:1286`,
whose `**` run closes two lines below the checkbox. The append therefore spliced text
mid-sentence and left it inside an unterminated bold run. Appending at the end of the LOGICAL
title only moves the bug (the title also ends mid-line); end-of-box is UNIFORM for wrapped and
unwrapped boxes alike, so no branch can pick wrong, and it leaves the checkbox line
byte-identical apart from its checkbox character.
