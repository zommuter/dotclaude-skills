# id:b890 -- `verify-negative-cases.py` runs a TRUNCATED `-mutation:` command and reports the wrong cause

Found 2026-09-05 by the chain-end review of run `relay-20260905-113859-5807`, on the
freshly-landed `tests/test_owner_accepted_keep_date_9628.sh`.

## The defect

`parse_directives()` iterates `head.splitlines()` and takes `CASE_RE.match(line).group(2)`
-- **the remainder of the matched line** -- as the whole mutation command. A declaration
authored as a heredoc across several comment lines therefore contributes only its FIRST
line. The id:9628 test declared:

```
# fails-against-mutation: python3 - <<'EOF'
# import re,pathlib
# ...
# EOF
```

and the command actually executed was the bare string `python3 - <<'EOF'`. Bash prints
`warning: here-document at line 1 delimited by end-of-file (wanted 'EOF')`, python reads an
empty stdin, and the pipeline **exits 0**. The runner only treats a NONZERO return as
`mutation command failed`, so the no-op passed its own sanity check, the test ran against
the UNMUTATED scratch tree, passed, and was reported:

```
VIOLATION: test_owner_accepted_keep_date_9628.sh: VACUOUS -- the test PASSES against its
declared negative case `mutation: python3 - <<'EOF'`. It demonstrates no killing power.
```

## Why this is worse than an ordinary false positive

The verdict is LOUD and CORRECT -- the case as declared does demonstrate no killing power --
but its stated CAUSE points at the test, and the test was fine. Verified by hand during the
review: with the pre-fix pattern restored, `split_head` keeps `@owner-accepted` and drops
`:2026-09-01`, so assertion (A) does fire. The reader is sent to rewrite a sound fixture.

The echoed command is in fact the whole evidence -- it prints as `python3 - <<'EOF'` with no
body -- but nothing SAYS that a truncation happened, and the surrounding text asserts the
opposite diagnosis. This is the `id:cbd2` shape one level up: the detector fires, and its
resolution walks the reader away from the fault.

## Acceptance

`verify-negative-cases.py` REFUSES a `-mutation:` argument that is not a complete bash
command, as a CONFIG ERROR (exit 2, the same class as a non-unique
`-assertion:` substring), naming the multi-line-declaration cause and the one-line
requirement -- instead of executing the fragment and reporting VACUOUS.

Grounded detector, measured on this tree 2026-09-05: `bash -n -c "$arg"` also exits **0**
for the truncated heredoc, so the return code is NOT the signal; it writes the
`here-document ... delimited by end-of-file` warning to **stderr**. Any stderr output from
`bash -n -c "$arg"` is the discriminator.

Negative control: a well-formed single-line mutation declaration in the same fixture run is
