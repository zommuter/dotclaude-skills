## From TODO

(observed 2026-07-10). `inject.sh add` mints a token and `take` consumes it in the discovery prelude, but **no event of any `kind` is written for either** (`grep -c '"kind":"inject' relay-events.jsonl` → 0, ever). So the only evidence that an injection was consumed is the token's *disappearance* from `inject.sh peek` — an absence, not a record. If the pool takes a unit and then drops it (verdict mis-mapped, filtered by an exclude/blocked path, lost across a round boundary), there is **no way to distinguish "consumed and dispatched" from "consumed and lost"**, and the user's work silently evaporates. Emit `{"kind":"inject-take","token":…,"repo":…,"verdict":…}` at consume time and carry the token onto the resulting `dispatch`/`integrate`/`handback` events so an injection is traceable end-to-end. Pairs with id:d484 — both are gaps in the relay's own observability, and both were found by a consumer trying to *watch* a pool rather than run one. <!-- id:f3a0 -->
