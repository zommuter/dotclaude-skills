# id:2381 -- `verify-negative-cases.py` reports a spurious VIOLATION when its sandbox teardown races

HAND-AUTHORED by relay review `relay-20260910-234645-16942` (2026-09-10). This note was NOT
produced by `tools/ledger-shrink.py`, so it carries no verbatim-reproduction claim.

## What was observed

Running the reviewer's §3d obligation in the review worktree:

```
python3 tests/verify-negative-cases.py --changed relay-ckpt-20260910-2115
```

reported, alongside four correctly-verified cases:

```
VIOLATION: test_review_box_tick_7c75.sh: RUNNER ERROR on `mutation: sed -i -e ...`:
  OSError: [Errno 39] Directory not empty: '/tmp/negcase-vgz6fjs3/tree/.git/objects'
TOTAL: 1 negative case(s) that do not fail for the declared reason, across 3 file(s) executed.
```

The same declaration then verified **green-now / red-there at its declared assertion** on two
subsequent runs -- once scoped to the single file, once through the identical `--changed`
invocation. Nothing in the test, the tool, or the declaration changed between the runs.

## Why it matters now and did not before

`id:abcc` (owner ruling 2026-09-10) wired this runner into `relay/scripts/integrate.sh` step
3d as a **pre-land** gate: it runs `--changed <canonical main HEAD>` inside the child's
worktree before the merge and hands back (`HANDBACK[verify-negatives]`, exit 38) on any
non-zero. So a teardown race in the runner's own temp-tree cleanup now costs a **merge**, and
the handback message names a negative-case violation that does not exist. The child gets
blamed for the runner's flake, and the operator's first move -- re-read the test -- is wasted.

Before `id:abcc` the runner was opt-in and a flake cost one re-run.

## The distinction the tool does not currently draw

`RUNNER ERROR` and "this negative case does not fail for the declared reason" are folded into
the same `VIOLATION` prefix and the same `TOTAL` count. They are different findings with
opposite remedies -- the id:6d7e shape one layer up:

* a real violation means **the declaration is wrong**; fix the test or the declaration;
* a runner error means **the harness failed**; retry, and fix the harness.

## Suggested shape (not a decision)

Separate the two: a distinct prefix and a distinct exit path for harness failures, so
`integrate.sh` can retry-or-surface a runner error rather than hand the unit back as a
negative-case violation. Whether a harness failure should still block the land is the owner's
call -- fail-closed is defensible, but it must say what actually happened.

The specific cleanup is an `OSError` while removing the sandbox `tree/.git/objects`; a
`shutil.rmtree(..., onerror=...)` retry, or simply not treating a teardown exception as a
case result, would cover the observed instance.
