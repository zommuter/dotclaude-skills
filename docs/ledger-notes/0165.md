## From ROADMAP

**`id:1b0e` shipped TWO independent mechanisms and the spec pins NEITHER of them -- only their
shared outcome, so a later refactor can delete either half and stay green.** Found 2026-09-08 by
mutation-testing `tests/test_workflow_check_hardening.sh`, not by reading it.

`id:1b0e`'s fix has two parts: an explicit `[[ ! -r "$f" ]]` readability guard, and the capture
and check of `awk`'s and `sed`'s exit status (previously discarded by a brace group, whose status
is only its LAST command's). Four mutants of `tests/lib-workflow-check.sh` were built in an
isolated mirror root (the tracked file was never modified) and run against the spec:

| mutant | spec result |
|---|---|
| A -- `awk_rc`/`sed_rc` capture+check REMOVED, `[[ ! -r ]]` kept | **11/11 PASS** |
| B -- `[[ ! -r ]]` REMOVED, status captures kept | **11/11 PASS** |
| C -- both removed | RED at `(b1)`, the declared `fails-against-assertion`, verbatim |
| D -- `'use strict';` removed from the prologue | RED at `(d1)` |

C and D establish that the spec is NOT vacuous, and C's failing line matches the file's own
`# fails-against-assertion:` declaration exactly. A and B establish the gap: the two mechanisms
are mutually redundant for the ONE case `(b1)` exercises (a `chmod 000` file), so each is
individually unpinned.

Whether that matters is arguable and is why it is filed small: specifying the OUTCOME rather than
the implementation is normally the right call. The counter-argument is that these two mechanisms
do NOT cover the same inputs. `[[ ! -r ]]` is a single check before the scan; the status captures
are the only thing that survives a TOCTOU (the file becoming unreadable between the guard and the
`sed`), and that path has no assertion at all. `sed_rc` was verified by hand to propagate out of
the redirected brace group (measured: `sed_rc=2` on a missing file), so the backstop does work --
it is simply untested by the suite.

**Acceptance**: the spec fails when `[[ ! -r ]]` alone is removed, and fails when the
`awk_rc`/`sed_rc` capture+check alone is removed. The natural shape is one assertion that
exercises the TOCTOU path directly (readable at guard time, unreadable at `sed` time -- e.g. via
a directory whose mode changes, or a `chmod` between the two), plus one that pins the `awk`
failure message. Do NOT weaken `(b1)`; add beside it.

**Done-check**: the two new assertions green on the shipped helper and RED against each
single-mechanism mutant; full `tests/run-tests.sh` green.

**Context**: `tests/lib-workflow-check.sh` (the readability guard and both status captures);
`tests/test_workflow_check_hardening.sh` `(b0)`-`(b2)`; `docs/ledger-notes/1b0e.md`.
