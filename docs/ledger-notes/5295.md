## The finding

Executor-contract rule 2c exists so that a child approaching its context limit hands back
cleanly instead of dying mid-unit and orphaning its worktree. On run
`relay-20260909-143257-21736` it did not fire once, and the reason is not executor
non-compliance -- the contract's own prescribed invocation returns `unknown`.

**The compliant child.** Agent `ae0093669425beefe` (`execute:dotclaude-skills`, item
`id:aa5e`) ran, verbatim, the command `executor-contract.md:81` tells it to run:

    ~/.claude/skills/relay/scripts/context-budget.sh --self --marker "$(pwd)"

`$(pwd)` was its worktree,
`/home/tobias/.cache/relay/worktrees/dotclaude-skills/relay-20260909-143257-21736-execute-aa5e-0`,
which is exactly what the contract means by `--marker "<your worktree path>"`. The result:

    self-transcript.sh: marker '<worktree path>' matched none of the 66 transcript(s)
      for session 88e0cae7-804a-48e4-9975-ef2568e05095 -- cannot identify which one is mine
    context-budget.sh: --self could not resolve this agent's own transcript
      (see self-transcript.sh above) (fail-open: verdict unknown)

It then continued and died `Prompt is too long` at 173,594 tokens.

**This is NOT `id:c219`.** That was a path-glob defect: the resolver searched only the flat
transcript shape and never saw Workflow-nested children. Here the resolver ENUMERATED all 66
transcripts correctly -- the nested glob works. What failed is the MARKER MATCH: the worktree
path did not discriminate among them. Same guard, second independent way to be inert, and the
`id:c219` fix does not cover it.

**Scale.** Of the four failed `execute:dotclaude-skills` children inspected
(`ae0093669425beefe`, `a110c471b6edaeae0`, `ac632a53259a64bb8`, `a7a9dcd3785dda07d`), THREE
never invoked `context-budget.sh` at all and the fourth got `unknown`. So rule 2c produced
zero usable verdicts across the run's execute lane. All 8 of the run's failures were
`Prompt is too long`, all on `execute` (Sonnet); `review`/`hard` (Opus) lost none.

## Why it matters more than the context cost itself

The context cost is separately tracked (`id:c3c1` preamble trim, `id:3846` its measured
insufficiency, `id:1095` the ~82k preamble, `id:5eeb` the linear-accumulation mechanism).
Those govern HOW OFTEN a child runs out. This item governs WHAT HAPPENS WHEN IT DOES:

- guard working  -> `route=` handback, worktree retired cleanly, item re-dispatchable.
- guard inert    -> API death mid-unit, worktree parked as `relay/orphan/*`, item blocked
                    until a human runs `/relay reconcile`.

Run `relay-20260909-143257-21736` produced four new parked orphans
(`...-execute-11a4-0`, `-799f-0`, `-aa5e-0`, `-b437-0`) by this exact route. Fixing the
preamble reduces the frequency; only this fixes the consequence.

## The open question this item must answer, not assume

What string is BOTH unique per child AND present in the child's own transcript? The worktree
path is unique but evidently not matched. Candidates to check before writing a fix: the item
id as it appears in the dispatch prompt; the branch name; a purpose-built dispatch nonce
injected by `relay-loop.js`. If the answer is "the dispatch prompt must carry a nonce", this
is not a pure `self-transcript.sh` change and the lane should be re-triaged at handoff.

**Acceptance**: a child dispatched inside a Workflow-nested run resolves its own transcript
via the command `executor-contract.md` prescribes, and `context-budget.sh --self` returns a
real verdict (`ok`/`over`), never `unknown`. Verified against a fixture reproducing the
nested shape with >1 sibling, so a marker that matches several transcripts still fails loudly
rather than picking one.

**Done-check**: a new hermetic test under `tests/` driving `self-transcript.sh` through
`--projects-root`/`--session-id` against a nested fixture with siblings; `make test` green.
Do NOT close this on a live run that happens not to die -- the guard returning `unknown` is
invisible unless asserted, which is how it survived this long.

## Second-order: the preflight said so and was under-read

`transcript-shape-preflight.sh` returned exit 4 INDETERMINATE at launch. That is the
documented "I could not look" verdict, explicitly NOT "all clear", and the orchestrator
(me) reported it as routine. It was routine at that instant -- no children had spawned yet --
but it left the run's only rule-2c liveness signal unverified, and the guard was in fact
broken for the whole run. Worth considering whether the preflight should re-run once, after
the first child is dispatched, rather than only at launch when it is structurally certain to
be indeterminate.
