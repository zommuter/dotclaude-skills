## The report, as filed

`id:0f1e`'s recorded audit-exempt scope is **ledger-only diffs** (`REVIEW_ME.md`, `ROADMAP.md`,
`TODO.md`, `RELAY_LOG.md`). It therefore does NOT cover `IDEAS.md` + `docs/ideas/*.md`
idea-capture commits. On `project_manager` that bought **three consecutive strong reviews with
nothing to audit** -- `RELAY_LOG.md` 2026-09-09 16:13, 2026-09-09 16:16, and 2026-09-10 11:48.

## Why it is a defect and not a nit

The exempt class exists so a window whose entire diff is bookkeeping does not consume a strong
review slot on an empty audit. An idea-capture commit is exactly that shape, so each such window
spends apex budget to conclude there was nothing to verify. The cost is per-window and recurring,
which is what distinguishes this from a one-off.

## Before building

Read `id:0f1e`'s own recorded scope first, not a restatement of it, and widen the class THERE
rather than adding a second exempt list -- two lists disagreeing is the failure mode this repo
has already paid for elsewhere. Check whether the exemption is keyed on PATHS or on a commit
shape before choosing where `IDEAS.md`/`docs/ideas/*.md` belongs.

## Acceptance sketch

An otherwise-empty window whose diff touches only `IDEAS.md`/`docs/ideas/*.md` (alone or with the
existing ledger set) is classified exactly as a ledger-only window is today, pinned by a test
that names the new paths; a window mixing idea capture with real code is NOT exempt.
