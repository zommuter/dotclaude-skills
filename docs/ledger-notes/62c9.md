## From ROADMAP

**46 tests are RED on an unmodified `main` because `node --check relay-loop.js` now fails,
and nothing in this repo changed -- the Node on this machine did.** Found 2026-09-08 during
a `/relay reconcile --all` sweep, while running the suite to verify an unrelated branch.

**The measurement.** `tests/run-tests.sh` on a clean `main` (`8d7e44bc`, working tree
carrying only unrelated ledger edits): **549 passed, 46 failed, 0 errored, 8 expected-red**.
Every one of the 46 fails the same way -- `FAIL: relay-loop.js fails node --check` or a
near-identical message -- and about 46 test files call `node --check "$JS"` directly on
`relay/scripts/relay-loop.js` as a template guard.

The error, against the committed `HEAD` blob rather than the working tree, so this is not a
local edit:

```
relay/scripts/relay-loop.js:4811
      return { error: 'discovery failed', runId: state.runId, … }
      ^^^^^^
SyntaxError: Illegal return statement
```

**The mechanism, proven rather than inferred.** `relay-loop.js` is a Workflow script: its
body is wrapped in an async function by the Workflow runtime, so top-level `await` (line
4807, `const r = await runRound()`) and top-level `return` (line 4811) are BOTH legal there.
`node --check` has no such wrapper and must pick a module goal, and each construct forces the
opposite one. Minimal reproduction on Node v26.8.1:

| file contents | `node --check` |
|---|---|
| top-level `return` only | OK (parsed as CommonJS) |
| top-level `await` only | OK (detected as ESM) |
| **both** | **SyntaxError** |

A file containing both is unparseable under either goal. `--check` is therefore the wrong
instrument for this file, and always was; it happened to agree with us until now.

**Why it started failing today.** `nodejs` was upgraded on this machine at **2026-09-08
08:10:22** (`26.7.0-1 -> 26.8.1-2`, `/var/log/pacman.log`), minutes before the sweep that
found this. The suite has not been green since.

**Strength of the causal claim, stated precisely.** That Node 26.7.0 ACCEPTED this file is
inferred, not measured: 26.7.0 could not be run to confirm it (the cached package needs
`libada.so.3`, and only `libada.so.4` remains on the system, so the binary will not load).
The inference rests on the bisect: all 8 most recent commits touching `relay-loop.js` are
BROKEN under 26.8.1, and each of those shipped under this repo's green-suite discipline with
these same ~46 guard tests present. They cannot all have landed red. What is NOT established
is which 26.8.x change did it.

**Why this is worth a ledger line.** The breakage is invisible from the git history -- the
last commit before it (`b028938e`) records `594/0/0/8-expected-red`, which was true when
written and is false now, with no intervening commit to blame. A session that trusts that
line instead of running the suite will conclude its own work broke 46 tests. The lesson is
the CLAUDE.md derived-doc rule with the environment as the drifting party: a green-suite
claim is a restatement, and it rots when the toolchain moves under it.

**The fix is a design choice, not a typo, and it is the owner's.** Two shapes:
(a) change the ~46 guard sites to wrap the source in an async function before checking (or
use an equivalent parse that models the Workflow runtime), which fixes the instrument and
leaves `relay-loop.js` alone; or (b) restructure `relay-loop.js` so it no longer mixes
top-level `await` with top-level `return`, which satisfies `--check` but bends the source to
suit a tool that does not model its runtime. (a) is the better-argued option -- the file's
constructs are legal where it actually executes -- but (b) is not unreasonable if
`--check`-ability is wanted as a property in itself. Do not pick one silently.

**Acceptance**: `tests/run-tests.sh` on a clean `main` is green again, with the template
guard still able to catch a genuine syntax error in `relay-loop.js` -- demonstrated by
introducing one and seeing the guard fire, not merely by the suite passing. **Done-check**:
full `make test` green, plus that deliberate-breakage probe.

**Context**: `relay/scripts/relay-loop.js` (lines ~4807-4811); the ~46 call sites,
`grep -rln 'node --check' tests/`; `node --version` (v26.8.1 at time of writing).

## Decision (owner, 2026-09-08)

**Option (a): repair the INSTRUMENT. `relay/scripts/relay-loop.js` is NOT to be
restructured.** The file's top-level `await` and top-level `return` are legal where it
actually executes -- the Workflow runtime wraps its body in an async function -- so the
defect is that `node --check` does not model that runtime, not that the source is wrong.
Option (b) (bend the source to suit the tool) is closed; do not re-open it.

The item is therefore re-laned `[INPUT - decision]` -> `[ROUTINE]`.

### The shape, prototyped and measured before handoff

A wrapper that models the runtime, i.e. the check becomes:

```bash
{ printf 'async function __relay_wf__(){ '; sed -E '1s/^export //' "$JS"; printf '\n}\n'; } > "$tmp"
node --check "$tmp"
```

Each of these was RUN on Node v26.8.1, not assumed:

| probe | result |
|---|---|
| pristine `relay-loop.js` through the wrapper | parses OK |
| stray `}` injected at line 2000 | caught, reported at line 2000 |
| unterminated string injected at line 2500 | caught, reported at line 2500 |

The prologue is joined to line 1 with no newline, so reported line numbers still match the
source. `relay-loop.js` contains exactly one ESM construct (`export const meta = {` on line
1) and zero `import` statements, which is why stripping a line-1 `export ` is sufficient --
and why a file that carries a line-initial `export `/`import ` ANYWHERE ELSE is outside what
this wrapper can model and must be refused LOUDLY rather than checked wrongly.

## Acceptance (supersedes the pre-decision Acceptance above)

- A shared helper -- suggested `tests/lib-workflow-check.sh`, exposing
  `workflow_node_check <file>` -- performs the Workflow-aware parse check.
- It parses the pristine `relay/scripts/relay-loop.js` green.
- It still CATCHES a genuine syntax error: a mutated copy exits non-zero. The fix must not
  be "make the check permissive".
- It FAILS LOUDLY (non-zero, message naming the file) when asked to check a file whose
  module scope it cannot model -- a line-initial `export ` or `import ` on any line other
  than line 1. No silent fallback, no silent pass.
- Every `tests/test_*.sh` site that today runs a bare `node --check` on `relay-loop.js`
  (52 files contain the string; ~46 guard `relay-loop.js` itself) is migrated to the helper.

**Done-check**: `bash tests/test_workflow_node_check_62c9.sh` green, then full
`tests/run-tests.sh` green -- which is also the item's own headline claim, since the ~46
guard sites are exactly what is red today.
