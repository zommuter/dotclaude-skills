Cheap fix for (b): a preflight/doctor check that every script named in the Makefile's relay install sets resolves under `~/.claude/skills/relay/scripts/`, run before dispatch or as a `relay-doctor.sh` item — mechanical, no LLM. Cost of NOT having it, measured: the guard was inert for every run from 2026-08-19 15:42 until 2026-08-20, and loderite attributes two merge conflicts in one run to the scan never happening. Re-checkable: delete a symlink under `~/.claude/skills/relay/scripts/` and assert the check FAILS loudly naming that script. **Sibling filed 2026-08-20: `id:78fe` is the INVERSE gap** — `make install` never prunes symlinks whose source is gone (a retired script stayed linked into `~/.claude` for ~3 weeks, surviving even a same-day `make install-relay`). Only both together make "is the live skill tree in sync with the repo?" answerable in both directions — and a dangling link is what makes an install-completeness check ambiguous in the first place, which slowed the `id:6570` diagnosis. <!-- id:16d5 -->
