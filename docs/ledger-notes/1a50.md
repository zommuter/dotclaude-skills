# id:1a50

`relay/references/hard-lanes.md` calls itself the lane SSOT while documenting the
SUPERSEDED vocabulary as current, and its own enforcers disagree with it.

## The divergence

The doc's headline section, `## The three lanes`, presents this as the set a new item
declares:

| Lane tag | per hard-lanes.md |
|---|---|
| `[HARD - pool]` | Bounded, unattended-safe apex work |
| `[HARD - meeting]` | Needs a design decision before anyone can build it |
| `[HARD - hands]` | Hardware / sudo / secret / on-device / rehearsal |

`hooks/pre-commit-lane-vocab.sh` HARD-DENIES exactly those three on any ADDED line
(owner chose hard-deny, id:9ef7 -- unlike the warn-only privacy gate), mapping them to:

    [HARD - pool]           -> [HARD]
    [HARD - meeting]        -> [INPUT - meeting]
    [HARD - decision gate]  -> [INPUT - decision]
    [HARD - hands]          -> no auto-default; four candidates, per-item judgment

`relay/scripts/lane-convert.sh` carries the same table and is the tool the hook names as
the fix. **Both cite `hard-lanes.md` as the SSOT** while enforcing the other set. The
hook's own comment records the flip: *"`[HARD - pool]` fell straight through once the
SSOT flipped"*.

## Also missing from the doc

`gather-human-backlog.sh` buckets three lanes the `## The three lanes` table never
mentions, and it lists them FIRST as the primary form with the venue-keyed set as the
legacy fallback:

    [INPUT - meeting]   -> hard_meeting     (/meeting decides it)
    [INPUT - decision]  -> human_decision   (human decides, NO meeting)
    [INPUT - access]    -> hard_hands       ("you run these")
    [INPUT - author]    -> hard_hands       (human-expert-authored content, id:2b0b)

So the doc is not merely spelling-stale: it is missing the `decision` / `access` /
`author` distinctions entirely, which is the whole point of the id:78ff split.

## Scope: DOC-ONLY

Verified 2026-09-08, so the fix does not cascade:

- `gather-human-backlog.sh` already documents and buckets BOTH vocabularies correctly.
- `hooks/pre-commit-lane-vocab.sh` and `lane-convert.sh` already hold the mapping.
- `tests/test_hard_lane_buckets.sh` **passes today** and tests BEHAVIOUR, not the prose,
  despite the doc's claim that it *"cross-checks the marker set against this doc"*. That
  claim is itself part of what is stale, and it is the reason the drift was never caught:
  the doc asserts a test pins it, and no test does.
