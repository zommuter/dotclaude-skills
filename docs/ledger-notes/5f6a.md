## The finding

`relay/scripts/transcript-shape-preflight.sh` classifies its ONE genuinely diagnostic
outcome as success, and its five uninformative ones as INDETERMINATE. The polarity is
inverted exactly where it matters.

Read from the script, not inferred:

- Lines 88, 93, 97, 107, 120 -- five `exit 4` INDETERMINATE branches. Every one is a
  "there is nothing to look at yet" condition: no session id, no projects root, resolver not
  executable, no session directory, no `agent-*.jsonl` transcripts yet. These are correct.
  The exit-4 code exists precisely so that "I could not look" never reads as "all clear",
  and `relay/SKILL.md` step 0d says so in those words.
- Line 190 -- case **(C) SKIPPED**, emitted when NO UNIQUELY-IDENTIFYING RELAY WORKTREE
  MARKER is found among the census. Control falls straight through to `exit 0` at line 205.

So the branch that fires when the marker fails to discriminate -- which IS the `id:5295`
defect, observed directly rather than inferred -- is reported as GREEN.

Both halves matter. **(A) passing is the proof that `id:5295` is not `id:c219`**: the nested

uniquely identifies its own child. And the script returned 0.

This is a strictly better reproduction than the transcript forensics that produced `id:5295`,
because it needs no dead child -- it is observable on any session with children, on demand.

## Why this is filed separately from id:5295

`id:5295` is the resolver defect: the marker does not discriminate. THIS item is the
detector defect: the thing built to notice that cannot report it. They have different fixes,
different files, and different failure modes, and fixing either alone leaves a real hole:

- fix `5295` only -> the detector still cannot distinguish "marker works" from "marker
  never tested", so the next regression is silent again.
- fix `5f6a` only -> the guard is still inert, but at least it says so.

Filed as a sibling rather than folded into `5295` because a handoff child held
`5295`'s claim and worktree (`relay-20260909-185356-12943-handoff-5295-0`, claimed 18:55)
at the moment this was found; CLAUDE.md's in-flight-automation rule prefers a follow-up item
over rewriting an item another run is working.

**Acceptance**: case (C) SKIPPED no longer exits 0. It returns INDETERMINATE (exit 4) at
minimum -- "the end-to-end path was not exercised" is by definition "I could not look", which
is what exit 4 means and what its five existing uses already encode. Consider exit 3 (FAIL)
when a census of N>0 transcripts yields ZERO discriminating markers, since that is a positive
observation of breakage rather than an absence of evidence; that distinction is a judgement
call and should be made explicitly, not defaulted.

**Done-check**: a hermetic test driving the script via `--projects-root`/`--session-id`
against a fixture whose transcripts carry NO discriminating marker; assert the exit code is
NOT 0 and that the (C) message still names why. Plus a second fixture WITH a discriminating
marker asserting exit 0 still holds, so the fix cannot be "always fail". `make test` green.

**Context**: `relay/scripts/transcript-shape-preflight.sh` (line 190 case (C), the fallthrough
to line 205 `exit 0`, and the five `exit 4` branches at 88/93/97/107/120),
`relay/SKILL.md` step 0d (the prose contract for what 0/3/4 mean).

## The orchestrator-side miss this makes concrete

At this run's launch the same script returned exit 4 INDETERMINATE ("no session directory
yet") and I reported it as routine. It WAS routine -- but the script is structurally
guaranteed to be uninformative at launch, which is the only place `relay/SKILL.md` step 0d
calls it. A check that can only run when it cannot yet see anything is a check in name only.
Re-running it once after the first child is dispatched is what turned it from INDETERMINATE
into the (C) SKIPPED evidence above, and that is a cheap change to step 0d worth considering
alongside the code fix.
