Two compounding causes: (1) manifest mode stages+commits the listed paths (line 85) but then hits the **id:aa93 dirty-tree refusal** (line 123, the *other* unstaged files) and exits 0 non-fatally — yet in the observed run the listed-path commit ALSO didn't land (needs root-cause: is `git commit` partial-staging the manifest paths, or does an empty/failed stage slip through `set -e`?); (2) nesting matters — a caller already holding an flock on the repo's `.git-lock-push.lock` (fd 8) cannot call git-lock-push (it `exec 8>`s the same file → 30s deadlock). **Impact:** any automation trying to auto-commit ONE scoped file into a repo that carries unrelated dirty state can silently lose the commit while believing it succeeded. The sampler worked around it with an explicit scoped partial commit (`git commit -- <path>`) under the lock + opportunistic clean-tree-only push (see `tools/quota-sample.sh` §3). **Fix candidates:** (a) make manifest mode return NON-zero (or a distinct code) when the intended paths didn't actually commit, so callers can't false-log success; (b) document that manifest mode requires an otherwise-clean tree and is unsuitable for chronically-dirty repos; (c) offer a `--scoped-commit-only` mode that commits the listed paths and SKIPS the rebase/push when the rest of the tree is dirty (what the sampler reimplemented); (d) note the fd-8 self-nesting deadlock in the script header.
