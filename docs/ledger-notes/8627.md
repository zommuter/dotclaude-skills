### The blind window, MEASURED on the live file

counting what it skips:

```
total=4930  scanned-as-code=3566  skipped-in-template=113  skipped-in-comment=1251
```

Only TWO lines open that 1,251-line comment state, and neither is a comment opener:

```

3968: // relay/orphan/* — for this unit's item that already carries >0 commits beyond base, i.e.
```

Both are `//` LINE comments. The rule `line ~ /\/\*/ && line !~ /\*\//` sees the `/*` inside
`orphan/*`, finds no `*/` on the line, and sets `in_comment`. The state then persists until a
line happens to contain `*/` -- line 3877 (`// process.*/require()/fs in this file.`) and line
4699 (`/* non-fatal — TTL backstop */`) respectively. Lines 3358-3876 and 3969-4698 are
ordinary executable code and are invisible to the module-scope scan.

For contrast, a character-level scanner over the same file finds **324** genuine
template-interior lines and **0** genuine block-comment-interior lines. The shipped model
reports 113 and 1,251. It is wrong in BOTH directions on the one file the helper exists to
guard.

### Severity: fail-OPEN, but backstopped -- no false green was found

A missed refusal is not a false green. `export`/`import` DECLARATIONS are SyntaxErrors inside a
function body, so `node --check` rejects them regardless; every constructed missed-refusal case
returned non-zero. What is lost is the CONTRACT the helper states for itself -- "refuse LOUDLY
rather than silently mis-model" -- and, specifically, the file-naming message that spec
assertions `(b2)` and `(c4b)` exist to pin, because roughly 40 of the 50 call sites redirect
stderr. Over that 1,251-line window the caller gets a non-zero exit naming a temp path instead.

### Three further false REFUSALS, all still live (fail-CLOSED)

Each was reproduced against the shipped helper; each is a legitimate file that is refused:

| fixture | verdict |
|---|---|
| escaped backtick on the template-OPENING line (`` const t = `x \` y ``, then a line-initial `export` inside the template) | REFUSED |
| escaped backtick on a line INSIDE a multi-line template (any backtick on the line clears `in_template`) | REFUSED |
| same-line close-then-open block comment (`const a = 1; /* x */ /*`), with the `export` inside the second comment | REFUSED |

Causes, in order: an escaped backtick makes the line's backtick count EVEN so the template never
opens; the exit rule is `line ~ /`/` (presence, not parity) so one escaped backtick closes the
state early; and the opener rule is suppressed by ANY `*/` on the line, including one that
closed an EARLIER comment.

### The header comment states a guarantee the code does not provide -- again

`id:e044`'s acceptance included *"Fix the helper's own comment in the same change -- it
currently states a guarantee the code does not provide."* The comment was rewritten, and the
new text makes two claims that the measurements above falsify:

- *"a real lexical scan (not just a line-initial substring) confirms is NOT inside a backticked
  template literal or a `/* */` block comment"* -- it is a per-line backtick-parity heuristic
  with no character-level tokenizer.
- *"A `//` line comment [...] never trips this refusal either way."* -- a `//` comment
  containing `/*` opens a 520-line blind window on the live file.

The INLINE comment further down is honest (*"a line-oriented scan with a small amount of lexical
state"*). The file contradicts itself; the header is the half that is read first.

**Acceptance**: a `//` line comment containing `/*` does not open a block-comment state (the two
live `relay/orphan/*` lines in `relay-loop.js` are scanned as code); an escaped backtick neither
suppresses a template opening nor closes an open one; a same-line `*/` belonging to an EARLIER
comment does not suppress a later `/*` opener on the same line; the four `id:e044` cases and the
genuine-line-5-export refusal all still behave as `tests/test_workflow_check_hardening.sh`
`(c1)`-`(c4)` pin them; and the helper's HEADER comment is corrected so it claims only what the
code does. A regression fixture asserts the skipped-line counts on `relay-loop.js` directly, so
the blind window cannot silently return.
