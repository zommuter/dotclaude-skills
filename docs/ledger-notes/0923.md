# id:0923 -- both ledger ratchets are INERT for every consumer of the INSTALLED path

Inbound `routed:9e1b` from an `ai-codebench` relay review, 2026-09-10. **Verified independently
here before ingesting**, and the verification changed the scope claim, so read the measurement
rather than the headline.

## Measured, both directions

    # from INSIDE dotclaude-skills (relay/scripts/todo-conformance.sh)
    grep -c 'ratchet INERT' -> 0          # baselines resolve, ratchets ACTIVE

    # from the INSTALLED path (~/.claude/skills/relay/scripts/todo-conformance.sh)
    head-length ratchet INERT -- no baseline at …/relay/scripts/../head-length-baseline.txt (id:0d7c)
    shape ratchet INERT      -- no baseline at …/relay/scripts/../shape-prose-baseline.txt  (id:2d17)

The baselines exist in the repo (`relay/head-length-baseline.txt`,
`relay/shape-prose-baseline.txt`, both regenerated 2026-09-09) and are declared in `relay_FILES`,
but `make install-relay` does not place them -- confirmed by running that target and then finding
both still absent from `~/.claude/skills/relay/`.

The script resolves its baseline relative to its own directory, so the path it computes depends on
WHICH copy is invoked. That is why this went unnoticed: every check run from inside this repo was
genuinely gated, and every check run anywhere else silently was not.

## Scope, corrected from the inbound wording

The inbound item says "fleet-wide". More precisely: **inert for every consumer EXCEPT a run invoked
from inside `dotclaude-skills` itself** -- which includes every other repo, every pool child, and
`relay-doctor` on any repo. So today's own conformance checks in this repo DID fire the ratchet
(relevant, because a lot of 2026-09-10's ledger work was gated on exactly those exit codes), while
the 40-odd other repos have had no length or shape ratchet at all.

## Why this was NOT fixed on the spot

Placing the baselines arms TWO gates across every repo at once, and the owner was away. A gate that
starts refusing commits in 40 repos with nobody watching is the wrong unattended change even when
the gate is correct -- the same reasoning that kept `AUTO_INTEGRATE_ORPHANS` off for that run. Filed
instead.

## What to check before fixing, because the obvious fix may be wrong

A single installed baseline file is only correct if the baseline is **repo-keyed internally**. It
now is -- `id:c655` (landed 2026-09-09) made both baselines key on `repo+ledger+id` via
`git-common-dir`, and regenerated both files in the 4-column format. So one shared file is the
intended design and installing it is right.

Confirm that before acting anyway: if any consumer still reads a 3-column row, installing a
4-column baseline fleet-wide would make it refuse legacy rows loudly (which `id:c655` intends) in
repos nobody has looked at yet. Expect first-run noise proportional to how long those repos have
gone ungated, and decide whether to regenerate per repo before arming.

## Acceptance

* Both baselines are present under `~/.claude/skills/relay/` after `make install-relay`.
* `~/.claude/skills/relay/scripts/todo-conformance.sh` reports no `ratchet INERT` line.
* The install-drift check (`id:1102`) covers NON-script `relay_FILES` too -- it passed clean an hour
  before this was found, because it compares `scripts/` only. That gap is the reason a declared file
  could go uninstalled unnoticed, and fixing only the symptom leaves it.
* A repo that has been ungated does not silently start failing commits: decide per repo whether to
  regenerate its baseline first.
