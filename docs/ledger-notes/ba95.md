## CORRECTION 2026-09-08, BEFORE ANY OF THE BELOW IS ACTED ON -- the central claim is WRONG

Edit declared per the README notes-are-editable rule; the original text is retained unchanged
below so the error is inspectable. **Read this section first; the analysis under
`## From ROADMAP` overstates the gap badly.**

**Stranded branches DO have a detector, and have since `id:2b4b`.** `relay-reconcile.sh`
carries `list_stranded()` (line 218), the `--all` sweep surfaces its output (line 283), and
three tests cover it: `test_reconcile_stranded_2b4b.sh`,
`test_reconcile_stranded_liveness_b99f.sh`, `test_reconcile_stranded_with_orphan_e53a.sh`. The
claim below that "reconcile enumerates only `relay/orphan/*`" is false, and it was reached the
lazy way -- by grepping for `relay/orphan` and reading the header, without ever grepping for
`stranded`. Exactly the "check for existing tooling before improvising" rule, missed by one
grep.

**Why the `4839` branch was not reported is a DIFFERENT and much narrower thing.**
`list_stranded`'s documented contract is to report a branch "which carries commits the trunk
does not have", enforced at line 246:

```sh
if [ "$(git -C "$r" rev-list --count "$trunk..$br" 2>/dev/null || echo 0)" -eq 0 ]; then continue; fi
```

That branch was **fully merged** -- 0 commits ahead of `main`, empty diff -- so it carried no
work the trunk lacked and was deliberately skipped. That is correct behaviour, not a hole:
`list_stranded` exists to surface work that could be LOST, and a merged branch has nothing to
lose. Its recommended disposition is `--discard`, which is why it is deliberately conservative
about what it names.

**What is genuinely undetected, stated at its real size.** A relay branch that is fully MERGED
but whose worktree is still registered, and a leftover directory under
`~/.cache/relay/worktrees/<repo>/` with no branch at all. Neither holds unmerged work, so
nothing can be lost; the cost is a stale worktree registration, a ref, and disk. The real harm
is the one this session actually suffered: it looks like hidden work and consumes an
investigation. That is a TIDINESS class, not a work-loss class, and it must stay clearly
distinguishable from a stranded branch -- which needs a human decision -- rather than being
folded in with it.

**The fleet measurement below still stands** (0 stranded branches, 0 registered relay
worktrees, 0 leftover directories across 57 repos) -- it was measured, not inferred, and is
unaffected by the mechanism error.

**Acceptance, REPLACING the one below:** the `--all` sweep reports a relay worktree whose
branch is merged into trunk as retirable residue, in its own clearly-labelled group, naming
`worktree-retire.sh --expect-merged` as the disposition; and it reports a leftover
`~/.cache/relay/worktrees/<repo>/*` directory that no worktree registration mentions. Stranded
(unmerged) branches keep their existing separate reporting, unchanged. **Done-check**: a
fixture repo with one merged-branch worktree plus one leftover directory is reported in the
retirable group and NOT in the stranded group; a fixture with an unmerged branch still reports
stranded and not retirable.

## From ROADMAP

**Relay residue is only visible when it lands in the `relay/orphan/*` namespace. A STRANDED
branch -- `relay/<runId>-<verdict>-repo-N`, never renamed into that namespace -- is invisible
to every tool we have, and so is a leftover worktree directory.** Found 2026-09-08 while
disposing of the parked orphans.

**How it surfaced.** A live worktree,
`~/.cache/relay/worktrees/dotclaude-skills/relay-20260907-100619-27900-execute-4839-0`, sat on
disk with its branch `relay/relay-20260907-100619-27900-execute-4839-0` still registered, left
behind by run `relay-20260907-100619-27900`. It appeared in `git worktree list` and nowhere
else. `relay-reconcile.sh --all` had been run repeatedly that morning and reported it not once
-- correctly, by its own contract.

**The mechanism, read from the code rather than inferred.** `relay-reconcile.sh` enumerates
`relay/orphan/*` and nothing else (its header documents this: it lists "the parked
`relay/orphan/*` branches"). `relay-doctor.sh` does not implement its own sweep -- it shells
out to `relay-reconcile.sh --all` at line 893 for the "parked orphan branches" section. So the
health check inherits the blindness exactly; there is no second opinion anywhere.

Two residue classes therefore have NO detector:

1. a `relay/*` branch that never reached the `relay/orphan/*` namespace, because the run died
   before the park step or the park was skipped;
2. a worktree DIRECTORY under `~/.cache/relay/worktrees/<repo>/` whose branch was already
   deleted, or which was never registered.

**Why this is worse than ordinary residue.** The orphan namespace is not merely where parked
work is filed -- it is the *only* thing that makes work visible for disposal. A branch that
misses it is not "parked and awaiting a decision"; it is silently retained forever, holding a
worktree, a ref, and its objects, with no surface that will ever mention it. The failure is
one-sided in the dangerous direction: the sweep says "3 parked orphans" and is believed,
because the number is specific and the tool ran cleanly.

**Fleet-wide measurement, taken before filing so this is not theoretical and not alarmist.**
Enumerated the 57 `classification = "own"` repos from `relay.toml` via `lib-own-repos.sh` (the
canonical set, honouring `# path:` -- not a `~/src` glob) and checked each:

| check | result |
|---|---|
| `relay/*` branches not under `relay/orphan/*` | **0 across 57 repos** (after this one was retired) |
| relay worktrees registered in `git worktree list` | **0** |
| leftover directories under `~/.cache/relay/worktrees/<repo>/` | **0** (the 67 per-repo dirs are empty shells) |

So the backlog is exactly one instance, now retired, and the fleet is clean today. This is a
DETECTOR gap, not an outstanding cleanup.

**Disposition of the instance.** Retired force-free with
`worktree-retire.sh <repo> <worktree> <branch> --expect-merged`: the branch was provably merged
into `main` (0 commits ahead, empty diff), so `git worktree remove` and `git branch -d` both
succeeded with no force op and nothing discarded. `--expect-merged` was passed deliberately so
a surprise would have failed loudly instead of silently parking the branch.

**Acceptance**: the cross-repo sweep reports a stranded `relay/*` branch and a leftover
`~/.cache/relay/worktrees/<repo>/*` directory, distinctly from a parked `relay/orphan/*` one,
naming the retire path for each -- so a run that dies before its park step cannot leave
invisible residue. Whether that lives in `relay-reconcile.sh` (widening what it enumerates) or
as a separate `relay-doctor.sh` section is an implementation call; if it goes in reconcile,
the two classes must stay DISTINGUISHABLE in the output, since a stranded branch needs
`worktree-retire.sh` first and cannot be fed to `--integrate` (which prefixes `relay/orphan/`).
**Done-check**: a fixture repo carrying one stranded branch plus one leftover directory is
reported by the sweep, and a fixture with neither is silent.

**Context**: `relay/scripts/relay-reconcile.sh` (the `relay/orphan/*` enumeration),
`relay/scripts/relay-doctor.sh:893` (which delegates to it),
`relay/scripts/worktree-retire.sh` (the force-free retire path),
`relay/scripts/lib-own-repos.sh` (the canonical own-repo set for any cross-repo sweep).
