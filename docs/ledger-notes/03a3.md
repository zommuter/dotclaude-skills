**WHAT MIGRATION NEEDS PER REPO, learned the expensive way here:**

- `--notes-dir` -- not every repo uses `docs/ledger-notes` (loderite uses
  `docs/roadmap-notes`, with 188 notes already there). Readers must DERIVE the directory
  from the pointer on the line rather than trust config; a hardcoded default was measured
  INERT in loderite while still reporting real-looking findings.
- The note SECTION HEADING differs per repo (`## From TODO` here vs
  `## Continuation detail (verbatim, moved from ...)` there). Parameterise the reader;
  rewriting 188 existing headings is its own migration with its own silent-drop risk.
- **Old-vocabulary lane tags in the LEADING run are a genuine prerequisite, and the remedy
  is repo-shaped.** loderite measured 129 old-vocab tokens on open items: **86 in the
  leading run** (the item's real lane, in retired vocabulary -- `lane-convert.sh` is the
  only path) and **43 in the body** (prose, travels with the body, harmless). The remedy
  that worked HERE -- give the item a real leading lane so the retired token demotes to
  prose -- only applies where the lane was being COMPUTED FROM prose, which was our case
  and is not loderite's. Split the two populations before calling either a blocker.
- `REVIEW_ME.md` is OUT of scope everywhere (owner-ratified 2026-09-02) -- compacted by
  ARCHIVING resolved boxes, never by relocating prose from open ones.
