## Wave-1 findings (added 2026-09-05, see the header declaration)

Wave 1 ran on **loderite** 2026-09-05 (repo #2 by bytes, per the table above). It applied
cleanly -- ROADMAP.md 322,886 -> 144,999, TODO.md 119,484 -> 63,802, 75 notes created, 82
appended, 0 overwritten, dispatch id sets byte-identical -- but produced four facts the tail
must carry. Each was verified against THIS repo's code, not taken on report.

**1. The shrink BLOCKS ITS OWN COMMIT wherever old-vocab lane tags survive, and the block is
structural.** `hooks/pre-commit-lane-vocab.sh:151` collects ADDED lines from the staged diff
and `:173` blocks when an added line introduces an old-vocab lane tag, while `:6` grandfathers
pre-existing tags only in UNCHANGED/context lines. A mechanical rewrite moves a line from
context to added, so the hook cannot distinguish "the shrink rewrote this line" from "somebody
typed a retired tag" -- it has no access to the distinction. Every repo in the tail carrying
old-vocab tags will hit this. loderite hit exactly one line (`id:4da9`).

**2. `[HARD - hands]` needs a HUMAN mid-wave, so those repos cannot run unattended.**
`relay/scripts/lane-convert.sh:16-21` never auto-converts it -- it "fragments across FOUR
candidate [INPUT] lanes" with "NO default for hands", and every such line is LEFT in place
with a stderr re-flag. loderite's owner ruled `[INPUT - access]` for `id:4da9` by hand. Budget
a human decision per `[HARD - hands]` line, per repo, BEFORE scheduling that repo's wave.

**3. Adopting `tools/ledger-detector-snapshot.sh` is GATED on taking its off-by-one fix.** The
tool extracted ids with `substr($3, RSTART+9, 4)`; `<!-- id:` is EIGHT characters and awk
`substr` is 1-indexed, so it captured the id's last THREE characters plus a space (`a91b` ->
`"91b "`). That is 16x fewer distinct values, so a departure can be MASKED by an unrelated
arrival and the set diff still looks clean. This note names the tool as the acceptance
instrument, so the fix is a PRECONDITION of adoption, not a footnote: a snapshot instrument
that silently collides its keys is worse than no instrument, because it produces a
clean-looking diff. Same shape as `id:4839`'s inert-versus-wrong argument -- the loud absence
beats the quiet falsehood. The fix is `RSTART+9` -> `RSTART+8`, one character.

**4. That fix is NOT FETCHABLE -- take the line, not a ref.** loderite's `cc16d1e1` is local
and unpushed: it is stacked on their wave-1 trim commit, which is committed-not-pushed pending
their owner, so it cannot be pushed independently without reordering history. Anyone adopting
the tool before that lands must apply the one-character change by hand.

**Also adopted from wave 1, procedural:** take the POST-snapshot on a CLEAN TREE. A
dirty-tree post-snapshot flipped loderite's `classify-repo` verdict `execute` -> `blocked`
while every id set it reports was byte-identical; re-taken after committing, it gives
`execute` -> `execute` with identical evidence. Since this note adopts
`ledger-detector-snapshot.sh` by name, the caveat is ours too.
