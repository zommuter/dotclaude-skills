### Constraints the fix must honour (carried verbatim in intent from the id:2b7a close)

- KEEP untracked files DIRTY. `git diff` NEVER shows untracked content, so "relax when
  the diff is empty" would blind these gates to the residue they mainly exist to catch
  (a child writing into the checkout leaves exactly untracked files).
- Relax ONLY the ` M`-with-empty-diff case, per entry, with the whole set required to
  qualify -- the same narrowing verify-isolation.sh already spells out.
- Fail-safe direction preserved: an unreadable repo, an erroring `git diff`, or any
  entry that cannot be classified all fall through to DIRTY. Note line 744 already
  captures the `status` exit status separately for this reason (id:a290 round-3); do
  not undo that while adding the diff cross-check.
- A GREEN TEST ON A NON-ANNEX OR CLEAN-INDEX REPO PROVES NOTHING. The filter only has
  work to do when the index is stale against annexed files, which is precisely why
  every other repo's worktrees retire without incident. The negative case must be an
  annex fixture with a stale index, in the shape of the table above.
- `git update-index --refresh` does NOT clear it (measured under id:3016, 2026-09-09).
  It is the obvious cheap fix and it does not work; do not re-add it.
- `git annex restage` is the display remedy, but only once `.git` is a gitdir FILE
  rather than a symlink (id:de4a). Through a symlinked `.git` it prints `restage ok`
  and silently no-ops.
