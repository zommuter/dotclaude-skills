## From TODO

Owner ask 2026-09-03, made while going AFK mid-session: *"be clever about continuing on your
own using adequate handoff/executor/review agents. When you cannot continue in good
conscience, wrap up the session, update the handover and `systemctl poweroff` without sudo."*

That instruction was given as free prose and executed by LLM judgment. It should be a skill.

### Why this is NOT `id:7e9a`

`7e9a` (`wrapup` / `handover` / `resume`) is about the ATTENDED end of a session -- close
cleanly, write what the next session needs, read it back. This is about the UNATTENDED
MIDDLE: the owner leaves while work is in flight, and the session must decide **on its own**
what it may still do, what it must not, and when to stop.

They share the handover artifact and should compose (`/afk` ends by invoking the `handover`
half of `7e9a`), but the hard part here is a POLICY, not a document.

### What the skill has to encode

1. **The authorization boundary.** Global `CLAUDE.md` already carries the rule: under an
   explicit unattended mode, do not block -- take the CONSERVATIVE default
   (surface-don't-act, skip-the-ambiguous) and leave the decision for later. The skill turns
   that from a paragraph into a checklist:
   - **MAY**: work already-ratified items; mechanical passes with a green suite; commit and
     push to the PRIVATE remote; file findings; dispatch agents.
   - **MUST NOT**: make an owner-level call (scope cut, GO/NO-GO, architecture, a design
     verdict); publish to a PUBLIC remote; relax a spec so code passes it; tick an item on a
     delegated agent's say-so.
2. **A stopping rule that is not "ran out of context".** "When you cannot continue in good
   conscience" needs an operational test. Candidates: the next item needs an owner decision;
   the suite is not green and the fix is not obvious; the remaining work is editorial rather
   than mechanical; two agents disagree. Decide the list.
3. **The agent pattern.** Independent handoff / executor / REVIEW agents, where the reviewer
   did not write what it reviews -- the standing rule that a green suite is not evidence when
   one agent wrote both code and test. Also: a delegated verdict is a RECOMMENDATION, never
   self-settling.
4. **Wrap-up sequence**: green suite, commit, push private, update the handover with what was
   done AND what was deliberately left, then power off. Note `systemctl poweroff` needs no
   sudo (polkit grants it to a logged-in user), which is why the owner said "without sudo".
5. **What the handover must carry that a normal one need not**: every decision the session
   DEFERRED rather than took, and why -- that is the whole audit trail of an unattended run.
