## From TODO

(observed 2026-07-10 while watching a live pool). `relay-loop.js:58` stamps every event with `state.ts`, the most recent **bash-produced** state timestamp, because the Workflow runtime forbids `Date.now()`/`new Date()` (noted at `relay-loop.js:53`). Consequences: (a) all events emitted within a round share one `ts`; (b) an `integrate` can carry an *earlier* `ts` than a `dispatch` that happened before it; (c) observed in the wild, two `integrate` lines in the same run disagreed on clock — one read `ts=12:43:00Z` beside `ckpt=relay-ckpt-…-1243` (local time, mislabelled `Z`), the other `ts=10:52:06Z` beside `ckpt=…-1251` (true UTC). Net: **event ordering and elapsed-time cannot be derived from `ts`**, and any future `--since` filter, burn-rate attribution, or forensic replay built on it is unsound. Fix options: mint the stamp in the shell producer that actually emits each event (`relay-state-write.sh event-append` already runs bash — stamp there, `date -u`, one clock), or add a monotonic `seq` counter per run and order by that. Audit every ISO stamp under `relay/scripts/` for `date -u` vs local-`date`+`Z` mislabelling while in there. Motivating incident: a monitoring predicate keyed on the event log matched six-day-old events; see the consumer's case notes. <!-- id:d484 -->
