## From TODO

Observed live 2026-09-04: `make test` reported a **HERMETICITY BREACH (`id:b54b`)** while all
578 tests passed. Nothing leaked. The drift was a RELAY worktree, created by a concurrent
`/relay review` child in its documented location.

### The defect

`tests/run-tests.sh`'s `snapshot_repo_state()` (`:113-127`) compares `git worktree list` before
and after the whole run and fails the suite on any drift. It EXCLUDES harness worktrees:

```sh
| grep -v '/\.claude/worktrees/' \
```

with a comment explaining that Claude Code creates one per isolated subagent, that this repo
routinely carries ~20, and that a concurrent agent starting or finishing mid-run would
otherwise trip a SPURIOUS breach.

**That reasoning applies verbatim to relay worktrees, and they are not excluded.** The relay's
own documented location is `~/.cache/relay/worktrees/<repo>/<runId>-<verdict>` -- deliberately
outside the repo tree "so it never pollutes status" (SKILL.md invariant 4). It still appears in
`git worktree list`, so it trips the guard.

Observed diff, verbatim:

```
1a2
> worktree /home/tobias/.cache/relay/worktrees/dotclaude-skills/relay-20260904-140928-23126-review
```

### Why it matters more than a one-off annoyance

**Any `/relay` run concurrent with `make test` reports a breach.** That is not an exotic
combination: relay executors run `make test` in their worktrees as their definition-of-done
check while sibling children hold worktrees of the same repo, which is the pool's normal
shape.

And the failure mode is the one this repo keeps paying for: **a guard that fires on legitimate
activity trains the operator to ignore it.** That is the same argument as `id:735f` (a flaky
check trains the re-run habit, and the re-run habit is what makes a true red invisible). A
hermeticity backstop that cries wolf during ordinary relay operation is worse than useless,
because its whole value is that it "ALWAYS fails the suite, independent of every individual
test's exit code".

### What to build

Exclude the relay worktree root from `snapshot_repo_state()` the way `.claude/worktrees/` is
excluded, for the identical stated reason.

**Derive the path, do not hardcode it.** `~/.cache/relay/worktrees` is the current default, but
a hardcoded literal here would repeat `id:d4d3` -- a path constant that silently stops matching
when the location moves, failing in whichever direction the guard was written to prevent. The
leak signature the guard exists for (a fixture writing into the CWD repo) is unaffected by the
exclusion, since such a worktree would not live under the relay root.

**Do not weaken it further than that.** The guard's value is that it is unconditional. Excluding
one well-known external root is not the same as making it advisory, and it must stay a suite
failure for anything else.

- **Acceptance**: a relay worktree present during a suite run does not trip the hermeticity
  backstop; a fixture that writes a `relay/*` ref or a worktree INTO the cwd repo still fails
  the suite unconditionally; and the excluded root is derived rather than hardcoded.

- **Done-check**: create a worktree under the relay root, run `make test`, and confirm it
  reports no breach; then create one inside the repo and confirm it still does.
