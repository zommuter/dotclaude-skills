### The reported symptom

Relay worktrees symlink `node_modules` into the main checkout. `pnpm <script>` then aborts
with `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`, so every test that shells out to `pnpm`
reads as RED -- in zkWhale that was 2 unit specs plus the whole Playwright `webServer`.

### The refusal that must be explicit

The obvious "fix" -- `CI=true`, or `confirmModulesPurge=false` -- **authorises pnpm to REMOVE
the modules directory**. Through the symlink that purges the MAIN checkout's `node_modules`,
destroying state no relay child owns. That fix must be refused explicitly and in writing,
because it is the first thing any session reaching this error will reach for.

### Correction (routed:37ce, id:9a72)

pnpm DOES run inside a relay worktree. The correct lever is
`PNPM_CONFIG_VERIFY_DEPS_BEFORE_RUN=false`, which disables the pre-run deps-status check and
authorises no removal at all. See `docs/ledger-notes/9a72.md`.

- **Acceptance**: the `CI=true` / `confirmModulesPurge=false` route is documented as REFUSED
  with its blast radius (main-checkout purge through the symlink) wherever a relay child
  configures pnpm.

- **Done-check**: a test or lint asserts neither `CI=true` nor `confirmModulesPurge` is set on
  the relay child's pnpm path.
