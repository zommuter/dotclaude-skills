## From TODO

### The constraint

`core.hooksPath` resolves ONE file per git event. Verified 2026-09-02:

```
$ git config --get core.hooksPath
/home/tobias/.config/git/hooks
$ ls -l ~/.config/git/hooks/pre-commit
pre-commit -> /home/tobias/src/dotclaude-skills/hooks/pre-commit-lane-vocab.sh
```

So `pre-commit-lane-vocab.sh` (`id:9ef7`) currently owns the slot, and
`pre-commit-ledger-grammar.sh` (`id:d667`) cannot be armed without taking it. Its
`make install-ledger-grammar-ratchet` target REFUSES to clobber -- exit 1, naming the
incumbent -- which is the right failure direction: silently replacing another ratchet
would disarm a live guard while reporting success.

This is not specific to these two hooks. It is structural, and every future `pre-commit`
guard hits it. The fleet already has three hook-shaped guards (lane vocab, the pre-push
privacy gate on a different event, and now the grammar ratchet) plus a `PreToolUse` family
that is unrelated. The next one will hit it again.

### What to build

A small `pre-commit` dispatcher that runs each registered hook in turn.

Design points, none of them free:

- **Exit semantics.** Non-zero if ANY hook blocks. The open question is whether to
  fail-fast on the first blocker or run all and report every finding. Prefer run-all:
  a committer who fixes one violation only to be blocked by the next one learns to reach
  for `--no-verify`, which is how a guard dies.
- **Never swallow stderr.** Each hook's output must reach the terminal verbatim. A
  dispatcher that buffers and drops is the silent-no-op class (`id:d35a`), and the
  no-swallow rule in CLAUDE.md applies directly.
- **Registration.** A directory of symlinks (`hooks/pre-commit.d/`) is the obvious shape
  and needs no config parsing. Ordering is then lexical, which is predictable but arbitrary;
  say so rather than pretending it is meaningful.
- **The install targets must cooperate.** `install-lane-ratchet` and
  `install-ledger-grammar-ratchet` should each register into the dispatcher rather than
  compete for the slot. Both currently write the slot directly, so both change.
- **Preserve the existing escape hatch.** `git commit --no-verify` must keep working
  exactly as documented for both hooks.

### Why it is worth doing rather than working around

The alternative is a combined mega-hook, which couples two unrelated guards into one file
and makes each one's tests harder to keep hermetic. The dispatcher keeps each guard a
standalone, separately testable script -- which is what both existing hooks already are.

### Relationship to id:d667

`d667` cannot be ARMED until this exists. That is a second, independent blocker on top of
`id:d05d` (the archive stub, which an armed hook would fire on for every
`roadmap-archive.sh` commit). Building `d667` was never blocked; only arming it is.
