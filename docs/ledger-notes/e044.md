## From ROADMAP

**`workflow_node_check`'s refusal scan reads PROSE as module syntax: a line starting with
`export `/`import ` inside a template literal or a `/* */` block refuses the whole file.**
Found 2026-09-08 by the `id:62c9` review. Latent today, and pointed straight at the one file
the helper exists to guard -- `relay/scripts/relay-loop.js` is 4,930 lines that are mostly
backticked prompt templates.

**Measured** against the landed `tests/lib-workflow-check.sh`:

| fixture | verdict |
|---|---|
| line-initial `export const fake = 1;` inside a backticked template literal | REFUSED |
| line-initial `export const fake = 1;` inside a `/* ... */` block comment | REFUSED |
| `  // export const x = 1;` (line comment, leading whitespace) | accepted, correct |
| `import("node:fs")` at line start (dynamic import, legal) | accepted, correct |
| `import ("node:fs")` at line start (same call, one space) | REFUSED |

**Why the helper's own comment is wrong about this.** It claims the anchor is chosen "so a
mid-line mention inside a string or a comment never trips this". True for a MID-LINE mention
and for `//`. False for a line-initial one inside a multi-line template literal or a block
comment, and those are the shapes a 4,930-line prompt-template file actually contains. The
scan is `awk 'NR>1 && /^[[:space:]]*(export|import)[[:space:]]/'` -- a line-oriented regex
with no notion of lexical context.

**The consequence, if it ever fires.** All 47 migrated guards go red at once, and the message
they print misdiagnoses the cause: it asserts an unmodellable ESM module scope for a file that
has none. That is a worse failure than the bare `node --check` this replaced, which at least
pointed at a real line. The trigger is one prompt template gaining a line that begins with
`export ` or `import ` -- entirely plausible in a file whose prompts discuss JavaScript.

**Verified as latent, not live**: `awk '/^[[:space:]]*(export|import)[[:space:]]/'` over
`relay/scripts/relay-loop.js` returns exactly one hit, line 1, which is the modelled case.
The suite is green (596/0/0/8-expected-red) and stays green.

It fails CLOSED, so this is a fragility, not a correctness hole -- filed at that weight.

**Acceptance**: a line-initial `export `/`import ` that sits inside a template literal or a
block comment does not trip the refusal, while a real module construct on any line but 1 still
does; `import (` with whitespace before the paren is accepted as the dynamic import it is.
Regression fixtures for all four cases live in `tests/test_workflow_node_check_62c9.sh` beside
its existing (c1)-(c4) block. Fix the helper's own comment in the same change -- it currently
states a guarantee the code does not provide. **Done-check**: those fixtures green, full
`tests/run-tests.sh` green.

**Context**: `tests/lib-workflow-check.sh` (the `bad_line` awk scan and the comment above it);
`tests/test_workflow_node_check_62c9.sh` assertions (c1)-(c4).
