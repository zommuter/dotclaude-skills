**Claim, and it is CONFIRMED by reading the code (2026-09-08).** `relay/scripts/discover-repos.sh`
fails OPEN on a corrupt registry. Its `overrides()` function (`:52-63`) runs a `python3 -c`
snippet that calls `tomllib.load` with no `try`/`except`. On a `TOMLDecodeError` the snippet
tracebacks to stderr and exits non-zero, but the caller is
`while IFS=$'\t' read -r name cls; do ... done < <(overrides)` -- a process substitution, so
the exit status is discarded, `set -e` cannot see it, `OVERRIDE` stays empty, and
classification proceeds with defaults. The script STILL emits its normal TSV on stdout. Any
stdout-only caller therefore sees a healthy classification while the canonical own-repo
registry is unparseable.

**How it was found.** Observed live 2026-09-08: a duplicate `fable_rechecked` key in a newly
added `[repos.wisenheimer]` block made the whole file unreadable to `tomllib`. It was caught
only because a directed handoff happened to be reading stderr.

**Why it matters here specifically.** `relay.toml` is THE own-repo set plus paths (the
no-not-invented-here rule in the global `CLAUDE.md` names it as the source of truth that must
never be re-derived from a `~/src/*` glob). A read site that degrades silently to "no
overrides" turns the source of truth into a fallback that is indistinguishable from success.
This is the `id:4347` no-silent-swallow class at a load-bearing read site.

**Proposal (as routed).** `relay.toml` readers should exit non-zero, or emit no rows, on a
parse failure rather than degrading; and callers should key on the EXIT CODE, not on stdout
being non-empty. Both halves are needed -- fixing only the reader leaves a caller that
already ignores the status.

**Scope note.** Worth auditing EVERY `tomllib` read site of `relay.toml` for the same shape,
not just `discover-repos.sh`. The process-substitution-swallows-status pattern is what makes
this invisible, and it is not specific to one script.
