# id:800f

Authored directly (not relocated by `tools/ledger-shrink.py`).

## From ROADMAP

### The gap

The ratified ledger line grammar (`id:b048`) admits exactly three shapes: BLANK, HEADING,
ITEM. The live corpus contains a fourth thing it has no home for: **section preamble
prose** -- blockquotes, explanatory paragraphs and one table that sit under a `##` heading
and belong to the SECTION, not to any item id.

`ROADMAP.md` carries 154 such lines after the `id:40c0` migration, and they are the single
largest remaining grammar class. They were REFUSED by that migration for a good reason:
they have no owning id, so there is no `docs/ledger-notes/<id>.md` to move them to.
Inventing a section-note convention is a format decision, not an executor's call.

### The options, none free

1. **A fourth legal shape.** Admit section prose under a heading. Simplest, and honest
   about how the ledgers are actually written -- but it reopens the grammar, and the
   grammar's value is that it is small enough to enforce mechanically.
2. **Section notes.** A per-heading note file, e.g. `docs/ledger-notes/_section-<slug>.md`,
   with the preamble relocated and a pointer left on the heading. Keeps the grammar at
   three shapes. Costs a new naming convention and a new class of file nothing currently
   reads.
3. **Delete or relocate case by case.** Some of the 154 are genuinely stale narration that
   should go; others are load-bearing context for a whole section. This is per-line
   judgment and cannot be mechanised.

### Why this must be decided before the fleet migration

`id:03a3` migrates 46 other repos. Whatever is decided here becomes the fleet rule. Deciding
it per-repo, or leaving it undecided while the migration runs, produces 47 different answers
and the grammar stops meaning one thing.

### Recommendation

Option 1, admitting a fourth shape, is the one I would put first -- but weakly, and the
owner should weigh it. The argument for it is that the 154 lines exist because section
context is genuinely useful to a reader, and a rule that forbids something useful gets
worked around rather than obeyed. The argument against is that a fourth shape is the thin
end of the wedge that produced the current state. Option 2 is the principled answer and
the more expensive one.

- **Acceptance**:

An `[INPUT - decision]` item's acceptance is a DECISION LIST, not a test (roadmap-lint's
NO-ACCEPTANCE rule is generic; a decision list is the correct shape for a human lane). The
decisions owed:

- D1. Does the grammar gain a FOURTH legal shape for section prose, or does section prose
  relocate to a per-heading note, or is it resolved case by case?
- D2. If a section note: what is its naming convention, and what reads it?
- D3. Does the answer bind the whole fleet via `id:03a3`, or may a repo differ?

- **Done-check**:

The decision is recorded with its rationale, `todo-conformance.sh`'s treatment of the 154
`grammar-line` findings follows from it, and `id:03a3` cites it so the fleet migration does not
produce 47 different answers.

## DECIDED 2026-09-03 -- owner-ratified: OPTION 1, TIGHTLY SPECIFIED

Appended to a note authored directly (it carries no "reproduced verbatim" claim, so nothing
above is falsified by this section).

### D1 -- the grammar gains a FOURTH legal shape: SECTION PREAMBLE

Admitted, but BOUNDED. The note recommended option 1 only weakly, fearing that a fourth
shape is the thin end of the wedge that produced the current state. The owner took it on a
strengthened argument: **the wedge risk comes from an UNBOUNDED shape, not from a fourth
one.** A tightly specified preamble is still mechanically enforceable, and mechanical
enforceability is where the grammar's value actually lives -- so the bounded form keeps the
property the three-shape rule was protecting.

The bounding conditions, all four required:

1. **CONTIGUOUS** -- one unbroken run of lines, not prose interleaved between items.
2. **IMMEDIATELY AFTER the heading** -- the run starts on the first non-blank line
   following a `##`-or-deeper heading.
3. **BEFORE the first ITEM** in that section -- once an item line appears, the section's
   preamble is closed and no further prose is admissible under that heading.
4. **UNDER A BYTE BUDGET** -- a preamble is capped; an over-budget one is a finding.

The second argument the owner weighed, from the note itself: the 154 lines exist because
section context is genuinely useful to a reader, and a rule that forbids something useful
gets worked around rather than obeyed.

### D2 -- not applicable

No section-note file class is created. D2 asked for a naming convention and a consumer only
if option 2 were chosen; it was not. The objection that carried weight against option 2: a
`_section-<slug>.md` file class that nothing currently reads is a vestige on arrival, which
the CLAUDE.md constraint-archaeology heuristic flags directly.

### D3 -- BINDS THE FLEET

The answer binds all 46 repos through `id:03a3`; a repo may not differ. This was the whole
reason the decision had to precede the migration -- deciding per-repo produces 47 answers
and the grammar stops meaning one thing.

### Implementation owed

- The byte budget's value is not fixed by this ruling -- set it from the live corpus so the
