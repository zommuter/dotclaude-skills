The owner's 2026-08-22 ruling was **"PROVE THE SHRINK FIRST, CHEAPLY -- do not migrate before
the mechanism is demonstrated"**, naming the exact experiment: dispatch one agent under
`agents/echo-runner.md` and one under the default, and diff their first-message input tokens.
Run today. First-request context (`input` + `cache_creation` + `cache_read`, the `id:10dc`
method), zero-tool or one-tool trivial task:

| Probe | model | first-request total |
|---|---|---|
| default `general-purpose` | claude-sonnet-5 | **73,369** |
| default `general-purpose` | claude-haiku-4-5 | **54,844** |
| `echo-runner` (custom def: minimal prompt, `tools: Bash`) | claude-haiku-4-5 | **29,796** |

**Matched-model result: 54,844 -> 29,796 = 25,048 tokens saved, 45.7% of the default
preamble.** A custom agent definition roughly HALVES the preamble. That is the number the
2026-08-22 ruling said "decides whether days of migration are worth doing", and it decides
YES.

**WHAT THIS DOES NOT ESTABLISH -- do not quote the 45.7% as an executor saving.**
`echo-runner` changes BOTH variables at once: it replaces the system prompt AND narrows
`tools:` to Bash alone. A real executor needs at least Read/Edit/Write/Glob/Grep, so its
achievable saving is strictly less than 45.7%. The split between system-prompt cost and
tool-definition cost is still unmeasured, and it decides whether the win comes from the
prompt (portable to any agent) or from the tool list (only available to genuinely
narrow-tool agents).

**Instruments for that split are BUILT and INSTALLED, awaiting a session restart:**
`agents/preamble-probe-wide.md` and `agents/preamble-probe-narrow.md` -- identical minimal
bodies, identical `model: sonnet`, differing ONLY in `tools:` (wide list vs `Bash` alone).
wide-vs-narrow isolates tool-definition cost; default-vs-wide isolates system-prompt cost.
Both are repo-managed per this item's own requirement (tracked, in `AGENT_FILES`, installed
by `make install-agents`, covered by `make status-agents`).

**NEW OPERATIONAL FINDING, learned by hitting it:** a newly installed agent definition is
**NOT visible to an already-running session** -- dispatching it fails with
`Agent type '<name>' not found`, listing only the types present at session start. The
registry is read once at startup. Consequences for the migration: `make install-agents` is
not sufficient to activate a definition, any rollout needs a session restart to take effect,
and a pool already running cannot pick up a newly added implementer type. `echo-runner` was
measurable today only because it had been installed in an earlier session.

**Extrapolation, flagged as extrapolation:** if the prompt-half of the saving carries to
Sonnet, a Sonnet executor's 73,369 preamble would fall toward ~40-50k. Against the measured
~176.7k Sonnet wall and the ~95k fixed floor recorded in `id:77d9`, that moves the floor from
54% of the window to roughly 35-40%. Whether it would have prevented any of the 5 deaths in
run `relay-20260908-174448-4421` is NOT established -- those died on accumulation during
work, and a lower floor buys headroom rather than immunity.

**STILL OPEN and explicitly NOT decided here: step (2), the subset.** This item's own text
warns that cutting the wrong half "silently degrades agent quality in a way no test catches",
and lists the global `CLAUDE.md` rules that demonstrably produce good agent behaviour. That
remains the owner's judgement call. What has changed is only that it is now worth making --
