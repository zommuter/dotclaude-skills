## From TODO

**PREVENT a delegated child editing outside its assigned worktree, rather than reminding it
to stay in or catching it afterwards.**

**Why prose is not the answer, measured.** `relay/references/executor-contract.md` already
mentions worktrees **18 times**. On run `relay-20260908-231617-32609`, **6 of 12** unit
children read no governing reference doc at all and **4 of 12** edited a repo anyway
(`docs/ledger-notes/c3c1.md`, and the handover's contract-read table). A nineteenth, more
emphatic mention reaches exactly the children who already read the file; the six who did not
are the ones this is for. Owner raised the reminder option 2026-09-09 and it was argued down
on this measurement, not on taste.

**The detection half ALREADY EXISTS -- do not rebuild it.** `relay/scripts/verify-isolation.sh`
(`id:f682`) is the deterministic, fail-safe integrator gate for exactly this failure: a child
that ran `git worktree add` correctly and then wrote every edit to the MAIN checkout, leaving
its worktree 0 commits ahead of base, so its "committed in worktree" self-report was a no-op.
Built after that happened for real (loderite R2 consumer handoff, 2026-07-14). Exit 0 = safe to
merge, exit 2 = isolation failure, never mutates. This item is the PREVENTION half and must
call that out rather than duplicate it.

**Shape.** A `PreToolUse` hook on `Edit`/`Write` (and the write-shaped `Bash` forms) that
resolves the target path and denies when it falls outside the worktree this session was
assigned. Same family as `destructive-git-guard.py` / `rm-force-guard.sh` / `pathspec-drop-guard.py`,
and the decisive property is the same one those have: **it binds a child that read nothing.**

**The hard part, stated so it is not discovered late.** The hook must learn WHICH worktree the
calling session was assigned. The hook's stdin payload carries `session_id`; the claim/lease
records and `relay/scripts/self-transcript.sh` (`id:ff30`, THE resolver for "where is the
calling agent's own transcript") are the existing machinery for session-to-run identity. A
child that legitimately has no assigned worktree (the reviewer/integrator, a `--drain` apex
turn, an ordinary interactive session) must pass through untouched -- so the predicate is
"this session HAS an assigned worktree AND is writing outside it", never "this path is a main
checkout".

**Fail direction is a real decision, not a default.** These hooks fail non-blocking: a hook
that exits non-zero makes Claude Code print stderr and RUN the command. A prevention hook that
cannot resolve the session's worktree therefore fails OPEN unless it is written not to. Decide
deliberately whether an unresolvable session denies (safe, but a bug wedges every write) or
passes (today's behaviour, and the silent hole). Recommend: pass, and LOG loudly, because a
wedge here stops all work while a miss is still caught by `verify-isolation.sh` at integrate.

**Scope: AUTHOR AND TEST ONLY.** Wiring it into `settings.json` `hooks.PreToolUse` is a
separate, owner-taken step -- the fleet's author-then-run split, and doubly so here because the
artefact constrains the very pool that would build it. Acceptance: a fixture proving a write
inside the assigned worktree passes and an otherwise identical write to the main checkout is
denied; `make test` green; NOT installed.
