### The defect

`roadmap-lint.sh`'s `DETAIL-POINTER-MISSING` check false-positives when ONE ledger line
carries the same note path in BOTH an `answer-src:` and a `detail:` pointer. `item_detail_path`
(`relay/scripts/roadmap-lint.sh:388`) captures both occurrences, `printf '%s'` emits the
concatenation, and the existence test then asks whether a two-paths-joined-by-a-newline file
exists. It does not, so the item is reported as pointing at a missing note. Live case: loderite
`id:ed3a` fires it although its note exists.

### The root cause is a mistaken belief about `-m1`, and that is the part worth recording

Line 394 reads:

```bash
hit="$( { grep -oP -m1 "[A-Za-z0-9_.-]+(?:/[A-Za-z0-9_.-]+)*/${idtok}\.md" <<<"${_rl_lines[$k]}" || true; } )"
```

and carries a comment explaining that `-m1` was chosen over `| head -1` to avoid SIGPIPE
becoming the pipeline status under `pipefail` (`id:81d5`). That reasoning is sound for the
problem it names and **does not do what the surrounding code needs**: `-m1` bounds the number
of matching LINES, never the number of matches WITHIN a line. The here-string is one line, so
both pointers match and both are printed.

Measured at intake, on this tree:

```
$ line='- [ ] [ROUTINE] **T** -- detail: `docs/ledger-notes/ed3a.md` <!-- answer-src: docs/ledger-notes/ed3a.md --> <!-- id:ed3a -->'
$ grep -oP -m1 "[A-Za-z0-9_.-]+(?:/[A-Za-z0-9_.-]+)*/ed3a\.md" <<<"$line"
docs/ledger-notes/ed3a.md
docs/ledger-notes/ed3a.md
```

Two lines out, from a one-line input, under `-m1`. The fix must take the FIRST match
explicitly (e.g. a `read -r` of the first output line, or a non-global capture) while keeping
the `id:81d5` no-pipe property the comment correctly protects. Replacing `-m1` with `| head -1`
would re-introduce exactly the SIGPIPE hazard that comment exists to prevent, so it is the
wrong repair.

- **Acceptance**: a ledger line carrying the same note path in both an `answer-src:` and a
  `detail:` pointer resolves to that ONE path, and no longer reports DETAIL-POINTER-MISSING
  when the note exists; the single-pointer and no-pointer cases are unchanged; and no pipe is
  introduced into the capture.

- **Done-check**: a hermetic test fixture with a double-pointer line asserts `roadmap-lint.sh`
  emits no DETAIL-POINTER-MISSING for it, and is RED against the current `-m1` capture.
