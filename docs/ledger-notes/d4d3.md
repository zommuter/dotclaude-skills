## From TODO

**BLOCKING for `id:03a3` on any repo not using `docs/ledger-notes`.** Found by the
trimmed-vs-untrimmed A/B the owner ordered 2026-09-04.

### The defect

`relay/scripts/classify-repo.sh:169-170` HARDCODES the notes directory, in BOTH the constant
and the regex literal:

```python
LEDGER_NOTES_DIR = "docs/ledger-notes"
LEDGER_NOTE_POINTER_RE = re.compile(r"docs/ledger-notes/([0-9A-Za-z][0-9A-Za-z._-]*)\.md")
```

There is no environment override. Other consumers already do this properly:

- **Derived from the pointer** (portable): `meeting/orphan-scan.sh`
  (`grep -oP 'detail:\s*\`\K[^\`]+'`), `relay/scripts/todo-conformance.sh`
  (`SHAPE_POINTER_RE` matches any directory).
- **Env-overridable**: `roadmap-lint.sh`, `ledger-slice.sh` (`LEDGER_NOTES_DIR`),
  `roundtrip-validate.py` (`--notes-dir`).
- **Hardcoded, no escape hatch**: `classify-repo.sh` alone.

### Why it is blocking rather than cosmetic

`classify-repo.sh` is where `id:f3d2` landed -- it folds note bytes into
`roadmap_bytes`/`todo_bytes` so that relocation cannot buy a false green on the prompt-size
gate. On a repo whose notes live elsewhere (loderite uses `docs/roadmap-notes`) the pointer
regex matches nothing, so the accounting silently adds **0 bytes**.

**That reopens exactly the failure `f3d2` was ratified to close, for 45 of the 46 repos
`id:03a3` will migrate.** The gate goes optimistic precisely where the migration has just
moved prose behind pointers.

`id:03a3`'s own note already warns that the hardcoded default was measured INERT in loderite.
This is that warning, located.

### CONFIRMED on a live repo 2026-09-04, and it is worse than "inert"

loderite checked rather than took our word. Their notes live in `docs/roadmap-notes`, so the
accounting adds ZERO. What the gate does not count, against what it does:

| | chars |
|---|---|
| `docs/roadmap-notes/` (209 files) -- INVISIBLE to the gate | **823,644** |
| `ROADMAP.md` + `TODO.md` -- what the gate counts | 447,575 |

**The invisible half is nearly TWICE the visible half.** So on that repo the gate is not
merely inert, it is OPTIMISTIC by a factor that GROWS every time the shrink convention works
as intended: every note written makes the gate blinder. That is the wrong direction for a
gate, and it is the exact inversion `id:f3d2` was ratified to prevent.

**Timing, recorded as CO-OCCURRENCE and explicitly NOT causation.** loderite had a real
prompt-size death the same day: a Sonnet executor on their `id:f2c9` killed by "Prompt is too
long", re-laned to apex, which completed the same item. So the failure this gate exists to
prevent occurred on the repo where the gate cannot see the larger half of the corpus. The
cause of that specific death remains unverified and its comparison confounded (see the caveats
in `id:e567`), so this is not evidence that ledger size killed that child. It is a good
argument for fixing this item regardless of what did.

**Deriving from the item's own pointer is the only fix that survives a repo changing its notes
directory AGAIN**, which is the property a hardcoded constant and an env override both lack.
