## 6. Gotchas learned tonight

- **A "passing" negative control that never ran proves nothing.** My first staged control raised
  `substring not found`, so the contract was never reverted and the *new* text passed. Caught only
  by reading the output, not the exit code. Redone staged: v14 → fails at (8a); v14+option(a) →
  fails at (8b); full → passes.
- **You can introduce a vacuity while fixing one.** My `hard-split` "existing enum" assertion could
  have been satisfied by my *own* Maintenance paragraph. Rescoped to text *before* rule 2c.
- **`md-merge` refuses a second id marker on a ledger line** (`id:6059`) — correct refusal, nothing
  written. Use a `children-of:`/`gated-on:` **typed edge** (sibling comment before the id) instead.
- **Inbox adoption wants the bracket-prefix form.** `[INBOUND routed:TOK from X]` + a single
  `<!-- id:YYYY -->`; the two-marker form is the refused shape. `inbox-done` accepted it.
- **`commit-ledger.sh` usage is `<repo> -m <msg> <path>…`** — flags after the repo, and `--help`
  is not a thing (it tries to resolve it as a repo name).
- **`relay-reconcile.sh` defers ALL integration on a dirty main tree** (`:338`, `:444`) — commit
  first or it only surfaces. And `--auto` refuses anything touching code/tests (that is the tool
  working, not a failure).
- **`grep -c 'context-budget' relay-loop.js` reads 0 BY DESIGN** for ff30 — the *child* is the
  caller, wired via the contract it reads. The usual unwired-detector cannot vouch for it.
