## 1. THE ONE THING THAT WENT WRONG — a defective archiver, my measurement, my revert

I ran `archive-closed.sh` for real across 6 repos on the strength of a `--dry-run` review, and
concluded it was "too conservative — 113 closed items, only 18 qualified, 16%". **Both the run
and the conclusion were wrong.**

- **The conclusion was a measurement artefact.** A categorisation of every top-level `[x]`
  across 6 repos × 3 ledgers found the twin-open guard fired **zero times**; the qualification
  rate is **100%**, not 16%. loderite's 113 were **110 already-archived stubs + 3 genuine
  items**. `046a` part (2) is therefore **closed as refuted** — there is nothing to relax, and
  both candidate relaxations were rejected on merit (the twin-disjunct is *vacuous by
  construction*, not merely empirically empty).
- **The run caused damage.** `archive-closed.sh:77` had dropped the `.*` between the id marker
  and the stub suffix — the character `roadmap-archive.sh:111` documents as load-bearing. Any
  stub with prose after its marker read as un-stubbed and was **re-archived every run,
  unboundedly**. Measured: duplicated ids in `ROADMAP.archive.md` went **3→8** (dotclaude-skills)
  and **1→16** (loderite); ~24 stubs, ~62 KB, committed and pushed.
- **Disposition, owner-authorized:** fix landed (`cba2e778`, with a real negative control — the
  test fails against the unfixed script with `FAIL(A2): stub id:1111 was rewritten`), all six
  archive commits **reverted**, archiver **re-run corrected**. 306 items this time vs 329; the
  ~23 delta was pure spurious re-archiving, not lost work. Duplicate counts are back to the
  pre-existing baseline, `resolve-gates` exits 0 and cross-ledger drift is 0 in all six.

**Generalized lesson worth keeping:** I measured "closed items" by counting `[x]` lines without
distinguishing genuine items from archive stubs, then built a verdict, a commit message and a
ledger entry on it. The stub/item distinction was visible in the data the whole time.

## 7. Gotchas learned — worth not rediscovering

- **A comment about code behaviour is a derived doc.** `lib-typed-edges.sh`'s header says gate
  resolution covers `TODO.md ∪ TODO.archive.md ∪ ROADMAP.md`, which would mean archiving a gate
  target out of ROADMAP breaks it. That describes a *different* consumer —
  `resolve-gates.sh:42-43` passes **all four** files. Reading the comment would have blocked a
  safe operation; reading the call site settled it.
- **An error message is an author's claim, not evidence.** `id:a376`'s throw said "an aim-driven
  ghost leaked", and that wording carried a wrong diagnosis into the ledger and sent the first
  analysis hunting a suppression bug that never existed.
- **A green suite proves least when one agent wrote both the code and the test.** Every agent
  result this session was re-derived against the original incident before commit; that is how
  the "nothing newly denies" imprecision and the archiver defect were both caught.
- **Confirm the BEFORE side of any harness is live.** The a615 harness genuinely produces 21
  dispatches under one prelude call; the archive harness genuinely moved 101 items. A before-side
  that errors or never reaches is not a passing negative control.
- **`git status --porcelain | awk '{print $2}'` then `git add $files` silently fails in zsh** —
  zsh does not word-split unquoted parameters. Stage per-file in a loop.
- **Use the canonical checker, not an improvised grep.** My duplicate-id grep flagged three
  REVIEW_ME false positives (markers *quoted in prose*); loderite's own
  `tools/check-ledger-duplicates.mjs` gives the real answer, and reported 2 pre-existing
  `OPEN-LIVE-CLOSED-ARCHIVE` violations (`id:aeeb`, `id:116f`) that are **not** mine.
