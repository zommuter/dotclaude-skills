# negative-case-exemptions.txt -- THE single reviewable allowlist for the `# fails-against:`
# discipline (TODO id:a73c; owner-decided 2026-08-14 under id:292b).
#
# Scope: read by BOTH `tests/lint-vacuous-fixtures.py` (mechanism (1): is the header
# declared?) and `tests/verify-negative-cases.py` (the runner: does the declared negative
# case actually fail, at the declared assertion?). Listing a file here excuses it from both.
#
# WHY ONE FILE: the rejected alternative was scattered `n/a` comments in the test files
# themselves. What has been excused must be auditable in one place, in one diff, by one
# `git log -p` on this file -- otherwise the blind spot grows silently, which is the exact
# failure class the item exists to close.
#
# Format -- one per line, reason MANDATORY (an unjustified exemption is a scattered `n/a`
# with extra steps; a missing reason is a CONFIG ERROR, exit 2):
#
#     test_foo.sh  -- why this file has no meaningful negative case
#
# Legitimate grounds: a harness/shape test that asserts a structural property of the suite
# itself rather than a fixed defect (its "negative case" would be a hypothetical repo layout,
# not a revision). NOT legitimate: "hard to write", "the ancestor is messy", "temporarily".
# A file with a `# roadmap:XXXX` header needs no entry -- a RED spec's redness IS the spec,
# and both tools carve it out automatically.
#
# (Deliberately EMPTY on first ship: every headerless test stays held, fail-closed, and the
#  runner reports the unverified population every run rather than hiding it behind excuses
#  nobody wrote down.)

# `fail() { echo "FAIL: $*"; exit 1; }` helper, so the runner -- which deliberately matches
# only `FAIL:`-prefixed lines, because scanning whole output lets a `PASS: (e) …` line
# satisfy an `(e)` expectation -- can never see WHICH assertion fired in them. Their
# `# fails-against-assertion:` could only ever be unverifiable. Verified by measurement
# 2026-09-01 (`grep -c 'FAIL:' <file>` == 0 for each).
#

# them to the `fail()` helper would make all 12 verifiable and is the right follow-up, but
# it edits 12 unrelated defect-fix tests and is NOT part of id:a73c -- do that as its own
